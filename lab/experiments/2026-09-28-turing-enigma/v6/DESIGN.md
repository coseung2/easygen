# Enigma V5 — 설계

v4(`../v4/`)의 스토리는 유지하고, 11개 독립 프리컴프를 하드컷으로 잇던 구조를 **마스터 컴프 하나에서 요소가 살아남아 변형되는 구조**로 다시 짠다. 기술 스택은 v4와 같다: AE 2021 ExtendScript 빌드 → aerender → FFmpeg 인코딩, 음악은 로컬 합성.

## 1. v4 분석

### 기술 결함
- `line()`으로 만든 모든 선이 화면 밖에 그려졌다. 셰이프 레이어의 기본 Position이 (540,960)인데 절대 좌표 정점을 넣어서 선이 +540,+960만큼 밀렸다. crib 대응선, 체크선, 옛 항로, 안전 항로, 마지막 화살표가 전부 안 보였다. 항로 장면에 빨간 원만 남은 이유다.
- 폰트 `HancomGothicBold`는 PostScript 이름이 아니라서 대체 폰트로 렌더됐을 가능성이 있다.
- `soundtrack.wav`가 v4 폴더에 없는데 v3 사운드가 경로로 들어갔다. 컷 타이밍(4초 격자)과 v4 장면 길이가 맞지 않는다.

|---|---|---|---|---|---|---|

### 구조 문제
- 11개 장면이 모두 비슷한 4–7초 카드이고, 배경색(라임/검정/아이보리)이 바뀌는 것 자체가 전환이다. "A가 변해서 B"가 아니라 "A 닫힘 → B 열림".
- 모든 장면이 문구로 설명한다. 그래픽이 문구를 뒷받침하지 못한다.
- 라임이 배경 면적으로 세 번 등장해 강조가 사라졌다.

## 2. 공통 모티프 — 실 한 가닥

영상 전체의 주인공은 **선 하나**다. 선은 사라지지 않고 모양만 바뀐다.

```
A→A 화살표 (끊어짐 = 불가능)
 → 말려서 로터의 원이 된다 (26칸 눈금, 한 칸만 빈틈)
 → 빈틈 속으로 들어가면 빈틈의 양쪽 모서리가 두 줄의 레일이 된다
 → 레일 위: 암호문 / 레일 아래: 예상 문구 WETTER
 → 같은 글자가 위아래로 만나는 칸 = 모순 (A→A 규칙 재등장, 라임)
 → 모순 없는 자리의 세로 대응선 6개가 다이얼의 바늘이 된다
 → Bombe: 다이얼 격자가 회전하며 탈락, 카운터 17,576 → 1
 → 마지막 다이얼 정지 (음악도 정지)
 → 다이얼에서 내려온 선이 암호문을 한 글자씩 풀어낸다 (사람의 대조)
 → 풀린 글자의 좌표가 해도 위의 점이 되고 위험 구역이 펼쳐진다
 → 옛 항로(점선)가 위험 구역을 지나고, 라임 선이 새 항로를 그린다
 → 새 항로가 곧게 펴지며 첫 장면의 A→A 화살표로 돌아온다
```

반복·발전시키는 개념: 빈틈(끊어진 선, 빠진 눈금, 모순 칸, 위험 구역을 피하는 굽음), 연결선, 회전, 정렬, 반복 패턴 속 예외 하나, 후보 제거, 하나만 남음.

## 3. 장면 전환 맵

| 전환 | A의 요소 | 변형 | B의 요소 |
|---|---|---|---|
| 1→2 | A→A 화살표의 선 | 선 양끝이 위로 말리며 원으로 닫힘(트림+회전), A 글자는 원 안으로 축소 | 로터 링 |
| 2→3 | 로터의 빈틈 | 빈틈 중심으로 스케일 1200%, 빈틈 양 모서리가 가로 레일로 | 암호문/예상 문구 레일 |
| 3→4 | 모순 없는 위치의 세로 대응선 6개 | 선이 회전해 짧아지며 다이얼 바늘로 | Bombe 다이얼 |
| 4→5 | 다이얼 격자 | 틀린 다이얼 탈락 가속 → 마지막 하나 | 정지한 라임 다이얼 |
| 5→6 | 라임 다이얼의 바늘 | 바늘이 아래로 떨어지며 세로선이 됨 | 해독 커서 |
| 6→7 | 해독된 좌표 문자 | 문자 줄이 한 점으로 수축, 해도 격자가 펼쳐짐 | 지도 위 위험 좌표 |
| 7→8 | 라임 새 항로 | 끝 화살촉을 기준으로 곧게 펴지며 수평선으로 | A→A 화살표 |

## 5. 디자인 규칙

### 그리드 (1080×1920)
- 세로 축: x = 540 하나. 모든 제목·메인 그래픽의 시각 중심이 이 축에 선다.
- 좌우 여백 96px (콘텐츠 폭 888px, x 96–984).
- 영역
  - 맥락 라벨: y 300 (작은 글자, 회색). 없어도 되는 장면은 비운다.
  - 메인 스테이지: 중심 y 900, 높이 약 900 (y 450–1350).
  - 카피: y 1480 (쇼츠 UI가 가리는 y 1560 아래는 비움).
- 상단 y 220 이하, 하단 y 1560 이하에는 글자를 두지 않는다.

### 타이포
- 한국어: Pretendard. 카피 Bold 64, 라벨 Medium 34.
- 기계 글자(암호문, 카운터, 좌표): Bahnschrift. 로터 글자 56, 레일 글자 96.
- 문구는 한 장면에 최대 한 줄. 설명은 그래픽이 먼저 한다.

### 색과 의미
| 색 | 값 | 의미 |
|---|---|---|
| 잉크 | #0B0E0F | 배경. 영상 내내 하나 |
| 아이보리 | #EFEDE3 | 기본 정보 |
| 회색 | #7A7F7B | 보조, 라벨 |
| 흐림 | #2B3031 | 탈락, 구조선, 해도 격자 |
| 라임 | #B8FF1F | 규칙, 빈틈, 모순의 발견, 살아남은 후보, 새 항로 — 이것만 |
| 적색 | #E0472F | 위험 구역(U-보트) 하나에만 |

### 요소와 의미
- 원 = 로터 / 다이얼 / 위험 범위
- 선 = 연결, 대응, 항로 (전부 같은 실)
- 블록·글자 = 문자, 후보
- 흐림으로 바뀜 = 탈락. 라임으로 바뀜 = 발견·확정

배경 사진(H3 로터, 바다)은 쓰지 않는다. 그래픽과 경쟁했다.

## 6. 카피

| 시점 | 카피 |
|---|---|
| 3.4초 | 하나는 불가능하다. |
| 14.6초 | 모순을 찾아라. |
| 33.6초 | 멈췄다. |
| 51.5초 | 정보는 항로를 바꿨다. |
| 55.2초 | 하나는 불가능했다. |
| 57.4초 | 그 하나가 에니그마의 빈틈이었다. |

라벨(작은 회색): `에니그마 로터`, `예상 문구 WETTER(날씨)`, `BOMBE`, `대조`, `수송선단`, `U-보트`.

사실 관계: 에니그마는 어떤 글자도 자기 자신으로 암호화하지 않는다. 이 성질로 crib(예상 문구)의 위치 후보를 지웠고, Bombe는 crib에서 나온 조건으로 로터 설정(휠 순서마다 17,576 = 26³ 위치)을 기계적으로 소거했다. 멈춘 설정은 사람이 대조해 확인했다. 해독 정보로 대서양 수송선단이 U-보트 위치를 피해 항로를 바꾼 사례가 있다. 화면의 암호문·좌표·항로는 원리를 보여주는 창작 도식이다.

## 7. crib 도식 데이터

- 암호문: `Q E X P L M R K`
- 예상 문구: `W E T T E R`
- 위치 0: 2번째 칸 E/E → 모순
- 위치 1: 6번째 칸 R/R → 모순
- 위치 2: 겹치는 글자 없음 → 통과
