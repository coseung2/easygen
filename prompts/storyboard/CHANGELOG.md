# storyboard

## 1.0 — candidate (2026-09-28)

- 사용자 지시로 제정: "클립별로 나눠서 시안을 뽑고, 클립 수는 유동. 대신 키네틱 타이포 시안과 미니맥스 맡길 영상시안이 둘 다 나와야 함." 턴마다 제각각이던 형식을 고정.
- 클립마다 A(키네틱 타이포) / B(MiniMax H3) 패널을 둘 다 만드는 2열 보드로 고정. 클립 수는 스키마가 강제하지 않는다.
- 2026-09-27 편집 보드 드리프트 사고의 후속 규칙 반영: H3 입력은 풀프레임 독립 레퍼런스, 잘라낸 보드 패널 금지.
- evals 없음. 출시 전 고정 입력 3개 이상 필요(제5조 §5-3).

### 1.0 보강 (2026-09-28, 2차)

- 사용자 지시: "이미지로 뽑아두고 레퍼 삼게 하자."
- 레퍼 전달을 계약으로 추가: A 원본 = 키네틱 목표 프레임, B 원본 = H3 `ref2v` 입력. 합성 보드는 검토·기록용. 출력 JSON에 `references[]`로 경로와 소비자를 기록.

### 1.0 보강 (2026-09-28, 3차)

- 사용자 지시: "스토리보드도 한 이미지 안에 그리드로."
- 보드 생성 방식을 고정: 생성 한 번으로 2열 × 클립 수 그리드 한 장. 칸에는 숫자·영문 라벨만, 한글 정보는 띠·표로.
- A 칸은 글자 자리를 블록으로 두고 정확한 문구는 코드 렌더에서 넣는다(생성 모델 한글 금지 유지).
- 레퍼 정의 갱신: 승인 후 A·B 풀프레임 패널을 따로 만들어 그 파일을 레퍼로 삼는다.
