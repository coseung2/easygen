# 다음 작업 계획

## 1. 목표
다계정으로 작업을 실행하고, 계정별 잔여분과 작업별 사용액을 한 화면에서 신뢰할 수 있게 확인한다. 추가 리팩터링/기능 확장보다 기존 기능의 실제 연결과 검증을 우선한다.

## 2. 범위 및 원칙
- 실제 값과 추정값을 구분한다.
- 조용한 fallback을 금지한다.
- 비용 귀속 근거를 저장한다.
- 기존 사용자 변경을 보존한다.
- 안정화 기준점 확보 전에는 여러 워커가 동일 작업 트리를 동시에 수정하지 않는다.

## 3. 단계별 작업

### 3.1 안정화 기준점 확보
작업:
- Git 상태와 변경 내용 확인
- 기존 사용자 변경 / 직전 안정화 패치 / 이후 변경 구분
- 현재 코드 기준 테스트 및 빌드 재실행
- 안정화 변경을 별도 커밋으로 정리
- 기존 DB 백업 후 마이그레이션 및 재실행에서 계정/작업 이력 유지 확인
완료 기준:
- 다음 작업의 기준 커밋이 명확함
- 기존 사용자 변경이 유실되지 않음
- 현재 코드 기준 테스트/빌드 결과가 기록됨
- DB 업그레이드 후 기존 데이터 유지가 확인됨

### 3.2 계정/크레딧 데이터 연결 완성
작업:
- 계정 목록 행 생성과 실제 Modal 계정 연결을 구분해 검증
- 등록 프로필이 어떤 workspace에 연결되는지 확인
- 연결 성공 / 인증 실패 / 청구 조회 불가 상태 구분
- 동일 workspace 중복 집계 방지
표시 원칙:
| 항목 | 표시 원칙 |
| --- | --- |
| 실제 잔여 크레딧 | 직접 확인 가능한 데이터가 있을 때만 실제 값으로 표시 |
| 사용자 설정 예산 잔여 | 실제 크레딧과 분리해 추정/예산 값으로 표시 |
| 사용액·청구액 | 크레딧 차감 전 사용료와 조정 후 청구액을 구분 |
| 조회 실패·stale 데이터 | 마지막 정상 값과 조회 시각을 보존하고 상태 표시. 0으로 덮어쓰지 않음 |
- 잔여 크레딧을 직접 조회할 수 없다면 임의 계산으로 실제 잔액처럼 표시하지 않음
완료 기준:
- 서로 다른 프로필에 대해 대상 workspace, 조회 가능 범위, 값의 기준, 갱신 상태가 구분됨

### 3.3 작업별 비용 수집 경로
작업:
- 로컬 작업 ID, 선택 계정, 원격 실행 식별자, 실행 시도 정보를 연결
- 청구 데이터를 작업에 귀속할 수 있는 근거를 저장
- 비용 상태를 실제 / 추정 / 미확인 / 반영 대기로 구분
- 계정 총사용료를 작업 수로 나누는 식의 단순 분배 금지
- 완료 직후 비용 미반영을 0으로 확정하지 않음
- 실패·취소 작업도 비용 확인 대상
- 재동기화 시 중복 합산 방지
완료 기준:
- 각 작업 사용료의 출처와 귀속 근거를 설명할 수 있음
- 실제/추정/미확인/반영 대기가 UI와 데이터에서 명확히 구분됨

### 3.4 사용량 UI 마무리
구조:
- 상단: 계정 표
- 하단: 작업별 사용량 표
- 큰 요약 카드/중첩 카드 래핑 추가 금지
계정 표 우선 열:
- 계정명·workspace
- 잔여 크레딧 또는 예산 잔여
- 이번 달 사용료
- 연결/동기화 상태
- 액션
작업 표 우선 열:
- 작업명
- 사용 계정
- 상태
- 완료 시각
- 사용료
세부 원칙:
- 계산 근거/상세 오류는 확장 영역에 배치
- 계정 5개, 작업 100개, 긴 이름, 조회 실패, 빈 목록, 작은 창에서 검증
- 불필요한 스크롤 최소화
완료 기준:
- 열 잘림, 과도한 여백, 반복 설명이 없음
- 계정 선택 → 작업 실행 → 사용량 확인 동선이 연결됨

### 3.5 실제 Tauri 앱 통합 검증
| 시나리오 | 확인사항 |
| --- | --- |
| 서로 다른 계정으로 작업 실행 | 의도한 계정으로 실행되고 결과/비용이 섞이지 않음 |
| 중지·보관된 계정 선택값 | 다른 계정으로 조용히 대체되지 않고 명확히 차단됨 |
| 실행 중 앱 종료·재시작 | 작업 이력이 복원되고 로컬 상태와 원격 실행 상태가 구분됨 |
| 취소·실패 후 늦은 이벤트 | 종료된 작업이 다시 실행 중으로 바뀌지 않음 |
| 청구 동기화 반복·통신 실패 | 중복 비용이 쌓이지 않고 마지막 정상 데이터가 유지됨 |
추가:
- 로컬 작업을 FAILED로 바꿨다는 이유만으로 원격 실행까지 중단됐다고 가정하지 않음
- 실제 유료 실행 검증과 모의 데이터/로컬 테스트를 구분함

- 진행 보고 형식: 워커명 / 실제 모델 / 작업 범위 / 검증 결과 / 막힌 점
