# 제1조 앱 정체성

## 1. Modal GUI는 무엇인가

Modal GUI는 **사용자 본인의 Modal GPU에서 오픈소스 생성 모델을 돌리고, 그 결과를 레퍼런스·스토리보드·편집·모션그래픽과 엮어 완성 영상까지 만드는 Windows 데스크톱 제작 스튜디오**다.

사용자가 하는 일은 세 가지로 요약된다.

1. 무엇을 만들지 정한다. 브리프, 레퍼런스, 스토리보드.
2. 소재를 만든다. Modal에서 영상·음악을 생성하고, 이미지·타이포·모션을 만든다.
3. 완성한다. 편집, 합성, 렌더, 결과 보관.

Modal 웹 UI, ComfyUI 화면, 렌더 도구를 오가지 않고 이 흐름을 한 앱에서 끝내는 것이 목표다.

이 저장소는 앱 개발과 함께, 앱에 넣을 제작 방식을 먼저 찾는 제작 실험도 병행한다. 둘의 경계와 승격 절차는 [제5조](05-two-tracks.md)에 있다.

## 2. 현재 구성 (2026-09-27 코드 기준)

| 층 | 역할 | 위치 |
| --- | --- | --- |
| 화면 | 새 작업, 스튜디오 캔버스, 작업 큐, 편집·모션, 결과물, 사용량, 연결, 설정 | `src/` (React, Tauri 2) |
| 코어 | 작업 상태의 기준, SQLite, 계정 풀, 사이드카 관리 | `src-tauri/` (Rust) |
| Modal 어댑터 | 계정 자격 주입, Modal 호출, 결과 다운로드, 비용 기록 | `worker/` (Python, JSONL) |
| GPU 작업자 | ComfyUI 워크플로로 MiniMax H3 영상 생성, YuE2 음악 생성 | `modal/app.py`, `modal/yue2_music.py` |
| 렌더러 | FFmpeg(무인), Autograph(무인), Cavalry·AE(프로젝트 준비) | `tools/renderers/`, `tools/*.jsx` |

화면이 있다는 사실과 외부 도구 연동이 실제로 동작한다는 사실은 별개다. 기능 상태를 말할 때는 `구현됨 / 테스트됨 / 실제 실행 확인됨`을 구분한다.

## 3. 무엇이 아닌가

- MiniMax 상용 API 클라이언트가 아니다. H3는 사용자 Modal 워크스페이스 안에서 오픈소스 모델로 돈다.
- 계정 제한이나 과금 정책을 우회하는 도구가 아니다. 계정 풀은 사용자가 권한을 가진 워크스페이스 사이의 정상적인 작업 분배만 한다.
- 브라우저 자동화나 웹 스크래핑으로 외부 서비스를 조작하지 않는다.
- 클라우드 협업 서비스가 아니다. 프로젝트와 결과는 로컬에 산다.

## 4. 제품 원칙

1. **실제 상태만 보여준다.** 알 수 없는 진행률, 추정 비용, 미검증 기능을 확정된 사실처럼 표시하지 않는다. 실제 청구액과 앱 추정치는 라벨을 나눈다.
2. **작업은 잃어버리지 않는다.** 앱을 껐다 켜도 원격 작업, 실행 이력, 결과 후보가 남는다.
3. **수정 가능한 결과를 남긴다.** MP4와 함께 소재, 장면 명세, 편집 원본, 사용한 파이프라인 버전을 보존한다. 정확한 문구·숫자·로고는 편집 가능한 레이어로 만든다.
4. **무엇으로 만들었는지 항상 추적된다.** 모든 결과는 어떤 파이프라인의 어떤 버전, 어떤 입력, 어떤 계정으로 만들어졌는지 되짚을 수 있어야 한다 (제3조).
5. **자격 증명은 화면과 DB 밖에 둔다.** OS 자격 증명 저장소만 쓰고, 로그·문서·레퍼런스 카드에 비밀값을 남기지 않는다.
6. **로컬 우선.** 사용자가 명시하지 않은 외부 업로드나 분석은 하지 않는다.
7. **제작 목적이 앞, 도구는 뒤.** 화면에는 "영상 생성", "타이포"처럼 목적을 먼저 보이고, 실행 도구와 모델은 선택 항목으로 둔다.

## 5. 데이터는 어디에 사는가

`MODAL_GUI_DATA_ROOT`는 생성 결과, 원자료, 검증 샘플을 보관하는 사용자가 설정한 로컬 디렉터리다. 각 환경에서 이 변수에 저장소 바깥의 경로를 지정한다. 아래 경로 표기는 이 디렉터리를 기준으로 하며, 해당 데이터는 저장소에 커밋하지 않는다.

| 종류 | 위치 | 규칙 |
| --- | --- | --- |
| 코드, 설계 문서, 헌법 | 저장소 (`modal-gui/`) | git으로 관리 |
| 레퍼런스 카드·종합 문서 | 저장소 `docs/research/motion-references/` | 가벼운 텍스트와 컨택트시트만 (제2조) |
| 파이프라인 정의 | 저장소 `pipelines/` | 매니페스트와 워크플로 JSON, git으로 관리 (제3조) |
| 노드 프롬프트 | 저장소 `prompts/` | 시스템 프롬프트와 입출력 계약, git으로 관리 (제5조) |
| Lab 실험 스크립트 | 저장소 `lab/` | 재사용할 만한 작은 코드만. App 코드는 import하지 않음 (제5조) |
| Lab 실험 결과 | `$MODAL_GUI_DATA_ROOT/lab/` | 실험마다 폴더 하나. 소재, 결과, `production.json`, `steps/`, `verdict.md` |
| 레퍼런스 원자료 | `$MODAL_GUI_DATA_ROOT/references/` | 영상·자막·프레임, git 밖 |
| 파이프라인 검증 샘플 | `$MODAL_GUI_DATA_ROOT/pipelines/` | 골든 입력과 출시 판정 결과 |
| 생성 결과·편집·납품물 | `$MODAL_GUI_DATA_ROOT/` (`h3-clips`, `music`, `edits`, `deliverables`, `series` 등) | git 밖 |
| 작업 상태·실행 이력 | 앱 데이터 폴더의 SQLite | 코어가 기준 |
| 자격 증명 | OS 자격 증명 저장소 | 다른 곳에 저장 금지 |
| 임시 분석 파일 | 시스템 임시 디렉터리 등 | 보존이 필요하면 작업이 끝나기 전에 `$MODAL_GUI_DATA_ROOT` 아래로 옮긴다 |

## 6. 현재 미준수 사항

- 저장소에 `pipelines/`가 아직 없고, 워크플로는 `$MODAL_GUI_DATA_ROOT/workflows/`, `$MODAL_GUI_DATA_ROOT/remote-workflows/`, `$MODAL_GUI_DATA_ROOT/prepared/`에 흩어져 있다. 이관 계획은 제3조 §8에 있다.
