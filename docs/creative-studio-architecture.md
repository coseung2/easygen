# 캔버스 기반 영상 제작 스튜디오 설계

작성일: 2026-09-27 (Asia/Seoul) · 버전: 0.1 · 상태: 구현을 위한 설계 초안

이 문서는 사용자와 합의한 제품 방향을 기준으로 화면, 노드, AI 대화, MCP 연결, 생성·렌더 실행, 데이터 보관과 구현 순서를 정의한다. 현재 저장소를 읽어 확인한 사실과 새로 제안하는 설계를 구분한다. 외부 서비스와 설치된 제작 도구의 실제 실행 가능 여부는 이번 문서 작성에서 검증하지 않았다.

## 1. 제품 방향

사용자가 아이디어와 레퍼런스를 모아 영상의 흐름을 잡고, 필요한 이미지·영상·음악·모션그래픽을 만든 뒤, 하나의 완성 영상으로 편집하는 제작 공간을 만든다.

사용자는 캔버스에서 제작 흐름과 소재의 관계를 보고, 스토리보드에서 장면 순서를 정하고, 타임라인에서 실제 재생 시간을 조절한다. 노드를 선택해 프롬프트를 입력하거나 이미지·영상이 포함된 채팅으로 작업을 지시할 수 있다. 생성 결과는 다음 작업에 연결하거나 여러 후보로 비교한다.

기본 사용자 흐름:

`브리프·레퍼런스 → 무드보드 → 스토리보드 → 샷별 소재 생성 → 후보 선택 → 모션·타이포 → 편집·합성 → 최종 출력`

### 1.1 사용자가 요청한 범위

- 여러 노드를 배치하고 연결하는 캔버스.
- 스토리보드와 무드보드로 제작 방향과 장면 흐름 구성.
- 영상 생성 노드의 직접 프롬프트 입력.
- 채팅에 이미지·영상 레퍼런스를 첨부하고 제작에 사용.
- Higgsfield MCP의 작업에 필요한 기능 활용.
- After Effects MCP를 통한 모션그래픽·키네틱 타이포·합성 작업.
- Modal에 올려둔 ComfyUI 워크플로 활용.
- GPT 이미지 등 이미지 생성 도구 활용.
- `coseung2/oauth-collect`를 참고한 ChatGPT OAuth 로그인과 계정 연결.
- 사용자가 여러 MCP 서버를 등록하고 관리하는 기능.

### 1.2 이번 설계의 기본 선택

| 항목 | 설계 기준 |
| --- | --- |
| 앱 형태 | 현재 Tauri 데스크톱 앱을 확장한다. 웹 서비스 배포·회원 가입·팀 협업은 후속 범위다. |
| 작업 단위 | 프로젝트 안에 캔버스, 스토리보드, 대화, 소재, 실행 이력을 둔다. |
| 노드 표현 | 이미지 생성·영상 생성·타이포처럼 작업 목적을 우선 표시하고, 실행 도구는 노드에서 선택한다. |
| 외부 도구 | MCP, 서비스 API, Modal SDK, 로컬 렌더러를 각각 적합한 연결 방식으로 지원한다. |
| GPT 인증 | ChatGPT OAuth 연결과 OpenAI API 키 연결을 별도 지원한다. OAuth 로그인 후 실제 이용 가능한 모델·기능을 확인한다. |
| 실행 | 노드 단독 실행과 선택한 흐름 실행을 모두 제공한다. 기본은 명시적 실행이다. |
| 저장 | 프로젝트 상태와 실행 이력은 로컬 DB, 큰 미디어 파일은 프로젝트 소재 폴더에 보관한다. |
| 기술 선택 | React/Tauri/Rust/Python 기반을 유지한다. 캔버스 라이브러리는 React Flow를 우선 후보로 검토한다. |

### 1.3 후속 범위

멀티유저 공동 편집, 클라우드 프로젝트 동기화, 자체 결제·구독, 공개 템플릿 마켓, 임의 코드 노드, ComfyUI 내부 편집기의 완전한 복제는 뒤로 둔다. 연결 서버와 제작 기능을 사용할 수 있는 구조를 먼저 완성한다.

## 2. 현재 앱에서 확인한 출발점

아래는 2026-09-27에 확인한 소스 구조다. 화면이나 함수가 존재한다는 사실과 외부 서비스에서 작업이 성공한다는 사실은 별도다.

| 현재 코드 | 확인된 내용 | 설계에 반영할 점 |
| --- | --- | --- |
| `src/App.tsx`, `src/app-config.ts` | 새 작업, 작업 큐, 편집·모션, 결과물, 사용량, 설정 화면 | 프로젝트 작업 공간을 추가하고 기존 화면의 기능을 연결한다. |
| `src/pages/GeneratePage.tsx`, `src/types.ts` | 영상/음악 모드, 프롬프트, 단일 입력 경로, 길이·해상도·변주·seed·계정 | 생성 노드의 공통 옵션으로 옮기고 여러 레퍼런스를 표현하는 형식으로 확장한다. |
| `src-tauri/src/database.rs` | `modal_profiles`, `jobs`, `job_events`, `usage_records` | 기존 계정·작업·비용 이력을 보존하면서 프로젝트와 노드 실행을 연결한다. |
| `worker/job_runner.py`, `modal/app.py` | 특정 H3 워크플로 선택과 Modal 호출, 결과 파일 다운로드 | 기존 H3 경로를 하나의 명시적 워크플로 어댑터로 등록한다. |
| `worker/job_runner.py`, `modal/yue2_music.py` | YuE2 음악 작업 호출 경로 | 음악 생성 노드에서 기존 기능을 재사용한다. |
| `src/EditPage.tsx`, `src/lib/pipeline.ts` | 클립 순서, 구간, 타이포 큐, 비트 분석, 렌더/프로젝트 준비 | 편집·합성 노드와 타임라인의 출발점으로 삼는다. |
| `tools/renderers/` | FFmpeg, Autograph, Cavalry 어댑터와 실행 모드 구분 | 완성 영상 출력과 편집 프로젝트 준비를 구분하는 계약을 유지한다. |

현재 코드의 제약도 초기 구현 계획에 포함한다.

- `fl2v`는 화면상 First/Last 모드지만 현재 입력 형식은 이미지 경로 하나다. 두 프레임을 독립적으로 받는 기능은 별도 구현·검증이 필요하다.
- H3 변환 코드는 특정 노드와 워크플로에 맞춰져 있다. 임의의 ComfyUI JSON을 모두 실행하는 범용 변환기로 취급하지 않는다.
- 작업 연결 이벤트의 `modal-{job_id}` 값은 로컬에서 만든 식별자다. 원격 실행을 다시 조회할 수 있는 실제 호출 ID 저장이 필요하다.
- 현재 `attach_job`과 `cancel_job` 처리만으로 원격 작업 재접속이나 원격 취소가 확인되는 것은 아니다. 실행 엔진 확장 시 이 경계를 먼저 보완한다.
- MCP 등록, 범용 MCP 호출, 앱 내부 AI 대화, GPT 이미지, AE MCP 연동은 확인한 현재 소스에서 기존 기능으로 전제하지 않는다.

기존 [계정·사용량 안정화 계획](next-work-plan.md)의 데이터 보존·비용 귀속·실행 복구 요구는 계속 유효하다. [렌더러 플러그인 문서](renderer-plugins.md)의 설치·버전 관련 내용은 해당 문서 작성 시점의 기록이므로 연동 시 다시 확인한다.

## 3. 핵심 개념과 관계

| 개념 | 의미 |
| --- | --- |
| 프로젝트 | 제작 목표, 캔버스, 스토리보드, 소재, 대화, 출력 설정을 묶는 작업 단위 |
| 노드 | 입력을 받아 기획·생성·가공·선택·출력 중 하나를 수행하는 편집 가능한 작업 정의 |
| 연결 | 노드 사이에서 어떤 입력이나 맥락을 전달하는지 나타내는 관계 |
| 샷 | 이야기 속 한 장면. 의도, 예상 길이, 문구, 선택된 소재, 제작 노드들을 연결한다. |
| 소재 | 업로드하거나 생성한 이미지·영상·음악·프로젝트 파일. 여러 노드가 같은 소재를 참조할 수 있다. |
| 실행 | 특정 버전의 노드와 입력을 실제 도구에 전달한 시도. 결과와 오류·비용을 남긴다. |
| 실행 도구 | Higgsfield 도구, AE 연결, Modal 워크플로, 이미지 API, 로컬 렌더러 등 |
| 스킬 | 기획·프롬프트·디자인 방법을 안내하는 지침. 실제 기능 호출은 연결된 도구가 담당한다. |

한 노드는 여러 번 실행할 수 있고, 한 실행은 여러 결과 후보를 만들 수 있다. 샷은 그중 하나를 선택해 사용한다. 새로 생성해도 이전 후보와 실행 이력은 남는다.

캔버스 위치는 화면 배치 정보다. 노드를 왼쪽으로 옮겼다는 이유로 영상의 샷 순서가 바뀌지 않는다. 샷 순서는 스토리보드가, 실제 컷 길이와 레이어 시간은 타임라인이 관리한다.

## 4. 화면 구성

### 4.1 프로젝트 작업 공간

| 영역 | 표시할 내용과 행동 |
| --- | --- |
| 상단 | 프로젝트명, 저장 상태, 되돌리기/다시 실행, 선택 실행, 전체 흐름 실행, 내보내기 |
| 왼쪽 패널 | 노드 추가, 프로젝트 소재, 샷 목록, 저장된 작업 묶음 |
| 중앙 | 확대·축소·이동 가능한 캔버스, 노드와 연결선, 그룹, 미니맵 |
| 오른쪽 패널 | 선택 노드의 설정·채팅·실행 이력. 선택이 없으면 프로젝트 대화와 기본 설정 |
| 하단 접이식 패널 | 선택한 스토리보드/편집 결과의 프리뷰와 타임라인, 실행 중 작업 |

캔버스를 넓게 쓰도록 양옆 패널을 접거나 크기를 조절할 수 있게 한다. 노드의 긴 프롬프트와 상세 옵션은 우측 패널에서 편집한다. 노드 카드에는 이름, 실행 도구, 짧은 입력 요약, 결과 썸네일, 상태, 실행 버튼을 둔다.

별도 화면은 프로젝트 목록, 소재 보관함, 연결 관리, 작업·사용량, 설정으로 구성한다. 연결 등록과 계정 관리는 제작 캔버스의 공간을 점유하지 않도록 별도 화면에 둔다.

### 4.2 캔버스 조작

- 노드 추가·복제·삭제, 다중 선택, 그룹 이동, 연결 생성·해제, 자동 정렬, 선택 영역 맞춤.
- 이미지·영상·오디오를 캔버스에 놓으면 소재로 등록하고 소재 노드를 만든다.
- 생성 노드의 입력 영역에 놓으면 해당 입력에 연결한다. 채팅에 놓으면 첨부로 추가한다.
- 입력란에서 글자를 편집할 때 캔버스 이동·삭제 단축키가 가로채지 않게 한다.
- 드래그와 동일한 일을 메뉴·파일 선택·키보드로도 수행할 수 있게 한다.
- 저장 완료, 저장 실패, 실행 대기, 실행 중, 실패, 결과 변경 필요 상태를 구별한다.
- 프로젝트 자동 저장과 실행 결과 저장을 구분하고, 앱을 다시 열면 같은 프로젝트와 선택 상태를 복원한다.

## 5. 노드 카탈로그

아래는 제품이 제공할 노드 종류다. 세부 도구의 모든 매개변수를 각각 노드로 노출하지 않고, 한 작업에 필요한 설정은 노드 안에 둔다.

| 노드 | 사용자가 하는 일 | 주요 입력 → 출력 |
| --- | --- | --- |
| 소재 | 이미지·영상·오디오·로고·프로젝트 파일 가져오기 | 파일 → 소재 참조 |
| 브리프 | 광고 목적, 제품 사실, 타깃, 필수 문구, 길이 정하기 | 메모·자료 → 제작 조건 |
| 무드보드 | 레퍼런스를 모으고 색감·재질·조명·움직임 지정 | 소재·메모 → 스타일 기준 |
| 스토리보드 | 샷 추가, 순서·예상 길이·카피·전환·필요 소재 설정 | 브리프·스타일 → 샷 목록 |
| 프롬프트 | 프롬프트 직접 작성, AI와 수정, 버전 선택 | 샷·스타일·참조 → 프롬프트 |
| 이미지 생성·수정 | 키비주얼, 제품 장면, 첫/끝 프레임, 부분 수정 | 프롬프트·이미지·마스크 → 이미지 후보 |
| 영상 생성 | 텍스트, 시작/끝 이미지, 제품·동작 레퍼런스로 생성 | 프롬프트·지원 입력 → 영상 후보 |
| 디자인 작업 | 지원되는 Higgsfield 기능 또는 등록한 디자인 도구 실행 | 작업 지시·소재 → 디자인 결과 |
| Comfy 워크플로 | 등록된 워크플로와 노출된 입력값 선택 | 이미지·영상·텍스트·설정 → 선언된 결과 |
| 모션그래픽 | 로고·도형·제품 그래픽의 움직임과 전환 설계 | 소재·모션 설정 → 구성 정보/그래픽 영상 |
| 키네틱 타이포 | 정확한 문구와 글꼴, 등장·퇴장·강조 타이밍 편집 | 텍스트·스타일·비트 → 타이포 구성/영상 |
| 음악·음성 | 음악, 나레이션, 효과음 제작 또는 기존 오디오 사용 | 설명·발화 원문·오디오 → 오디오·시간 정보 |
| 후보 선택 | 결과 비교, 선택 고정, 새 후보 요청 | 후보 집합 → 선택된 소재 |
| 편집·합성 | 컷 순서·길이·레이어·전환·오디오 결합 | 영상·그래픽·오디오 → 타임라인/프리뷰 |
| 검토·내보내기 | 프리뷰 확인, 출력 형식 선택, 최종 파일 저장 | 타임라인/프로젝트 → 영상 또는 편집 프로젝트 |
| 도구 실행 | 전용 화면이 없는 MCP 도구의 구조화된 입력 편집 | 도구 입력 형식 → 원본 결과/연결 가능한 결과 |

사운드는 AE에서 코드로 제작하는 방식과 Modal의 YuE2 음악 생성 방식으로 조달한다. 기존 오디오 파일을 소재로 가져오는 방식도 함께 지원한다.

### 5.1 노드와 샷의 관계

스토리보드의 샷 카드에서 `캔버스에 펼치기`를 누르면 해당 샷에 필요한 생성·선택 노드를 만든다. 관련 노드는 샷 그룹으로 묶되, 다른 샷의 소재나 공통 무드보드도 참조할 수 있다.

프롬프트 노드는 여러 생성 작업이 문구를 공유하거나 따로 관리할 때 사용한다. 간단한 작업은 이미지·영상 생성 노드에 직접 프롬프트를 입력할 수 있다. 연결된 프롬프트와 로컬 문구를 함께 쓸 때는 보완 방식과 우선순위를 화면에서 확인할 수 있어야 한다.

반복 사용되는 노드 그룹은 이름을 붙여 템플릿으로 저장한다. 템플릿에는 외부 연결의 실제 비밀값을 포함하지 않고 필요한 기능과 입력 슬롯을 저장한다.

### 5.2 생성 노드의 공통 구성

| 구성 | 내용 |
| --- | --- |
| 프롬프트 | 직접 편집 가능한 원문, 선택 버전, AI로 다듬기 |
| 참조 | 이미지·영상 첨부, 역할, 영상 구간, 연결된 입력 |
| 실행 도구 | 공급자, 모델 또는 워크플로, 연결 계정 |
| 생성 설정 | 지원되는 길이·화면비·해상도·seed·후보 수 |
| 실행 상태 | 대기·생성·결과 수신·실패, 확인 가능한 진행 정보 |
| 결과 | 썸네일/재생, 후보 비교, 선택, 다음 노드 연결 |
| 이력 | 실행 당시 프롬프트·입력·설정·도구 버전·비용과 결과 |

실행 도구가 지원하지 않는 옵션은 사용 가능하게 표시하지 않는다. 예를 들어 동영상 참조가 불가능한 모델에서는 해당 입력을 연결할 때 이유를 알리고, 필요하면 별도의 프레임 추출 작업으로 전환한다.

## 6. 연결선과 데이터 전달

연결은 두 가지로 구분한다.

- **자료 연결:** 이미지·영상·오디오·프롬프트·타임라인 등 실행에 사용하는 입력. 실행 순서를 결정한다.
- **맥락 연결:** 무드보드·브리프·샷 의도를 AI가 참고하도록 전달한다. 연결만으로 생성 작업을 시작하지 않는다.

포트는 `Text`, `Brief`, `StyleGuide`, `Image`, `Video`, `Audio`, `Mask`, `ShotList`, `MotionSpec`, `Timeline`, `ProjectFile`, `Json` 등의 자료형과 단일/복수 여부를 선언한다. 도구가 반환한 임의 JSON을 자동으로 영상이나 타임라인으로 간주하지 않는다.

자료 연결은 순환이 없는 그래프로 실행한다. 반복 수정은 노드를 다시 실행해 새 버전을 만드는 방식으로 처리한다. 맞지 않는 포트 연결은 만들 때 설명하고, 변환이 필요하면 프레임 추출·트림·형식 변환 같은 작업을 명시한다.

브리프나 프롬프트가 바뀌면 영향을 받는 결과에 `입력 변경됨`을 표시한다. 기존 결과는 계속 재생할 수 있고, 변경된 부분을 사용자가 실행할 때 갱신한다. 상위 노드 변경만으로 유료 생성이 다시 시작되지 않는다.

## 7. 채팅과 레퍼런스

### 7.1 대화 범위

대화는 프로젝트 전체 대화와 노드별 대화로 저장한다. 우측 패널에서 현재 대상과 포함되는 자료를 표시한다. 노드를 선택하면 해당 노드의 대화를 열고, 선택을 해제하면 프로젝트 대화로 돌아간다.

프로젝트 대화에서는 브리프 정리, 무드보드 해석, 샷 분할, 노드 구성과 연결을 지원한다. 노드 대화에서는 프롬프트 수정, 후보 평가, 모션·타이포 지시와 해당 노드 실행을 지원한다.

채팅에서 확정한 프롬프트와 설정은 노드의 편집 가능한 필드에 반영한다. 실행 시에는 당시 값을 별도 기록한다. 대화 전체를 그대로 생성 모델에 보내지 않는다.

### 7.2 이미지·영상 첨부

첨부 자료는 프로젝트 소재로 한 번 등록하고 대화와 노드가 함께 참조한다. 역할을 `제품 외형`, `스타일`, `시작 프레임`, `끝 프레임`, `인물`, `동작·카메라`, `레이아웃`, `오디오`처럼 지정할 수 있게 한다.

영상에는 사용할 시작·종료 구간과 추출 프레임을 지정할 수 있다. 원본 동영상을 이해하는 AI와 프레임만 이해하는 AI를 구분한다. 프레임 분석을 사용했다면 원본 움직임 전체를 분석한 것처럼 설명하지 않는다.

생성 엔진이 받는 레퍼런스 형식과 대화 AI가 이해하는 첨부 형식은 다를 수 있다. 대화에서 영상을 참고했다는 이유로 그 파일이 생성 엔진에도 전달됐다고 표시하지 않는다. 실행 입력 목록에서 실제로 전달할 파일과 역할을 확인할 수 있게 한다.

### 7.3 AI가 하는 일과 앱이 하는 일

| 담당 | 책임 |
| --- | --- |
| 대화 AI | 기획 제안, 카피·프롬프트 작성, 참조 해석, 도구 선택 제안, 구조화된 편집 요청 |
| 앱 | 입력 검증, 노드·연결 저장, 실행 요청, 파일 전달, 결과 등록, 상태·비용 추적 |
| 외부 도구 | 실제 이미지·영상 생성, AE 작업, Comfy 워크플로 실행, 렌더 |

자연어 요청은 노드 생성·연결·설정 변경과 같은 구조화된 변경으로 적용하고 되돌릴 수 있게 한다. 단순한 기획 대화로 유료 생성까지 시작하지 않는다. 사용자의 생성 지시나 실행 버튼은 해당 실행 범위의 시작으로 처리하고, 추가 후보·다른 서비스 사용이 필요하면 범위를 명확히 한다.

모델에 보낼 맥락은 관련 브리프, 연결된 소재, 해당 샷, 최신 확정 설정을 우선한다. 모든 프로젝트 파일·모든 MCP 도구 설명·전체 대화를 매번 보내지 않는다.

### 7.4 스킬 활용

영상 프롬프트 가이드와 디자인 지침은 앱에서 버전을 관리하는 지침으로 등록한다. 프로젝트 또는 노드에 적용할 지침을 선택하고, 실행에 사용한 지침 버전을 남긴다. 개발자의 개인 스킬 경로에 의존하지 않도록 앱에 포함하거나 명시적으로 가져오는 구조로 만든다.

`commercial-video-prompt` 가이드는 완성형 광고 영상 프롬프트를 작성하거나 내보낼 때 적용한다. 원문 텍스트 보존, 검증된 제품 정보, 모션·카메라·시간 구조, 마지막 안정 구간을 유지한다. 기본 6,000~6,500자 및 7,000자 상한은 그 출력 모드의 규격이다. 실제 모델·워크플로 입력 한도가 더 작다면 모델용 변환본을 별도 저장하며, 원본을 조용히 잘라 보내지 않는다.

한 샷의 프롬프트나 일반 채팅 답변에 전체 광고 프롬프트 규격을 강제하지 않는다. 화면비·해상도·fps는 생성/출력 설정으로 보관한다. 최종 프롬프트만 출력하는 규칙은 프롬프트 내보내기에 적용한다.

## 8. 스토리보드·타임라인·모션

스토리보드의 샷에는 안정적인 `shot_id`, 순서, 광고 역할, 설명, 예상 길이, 정확한 화면 문구, 나레이션, 연결된 제작 노드, 선택 소재를 둔다. 소재를 만들기 전에는 기획을, 만든 후에는 실제 선택 결과를 보여준다.

타임라인은 선택된 소재를 바탕으로 컷의 시작·끝, 소재 내부 사용 구간, 오디오, 그래픽 레이어, 전환을 편집한다. 스토리보드 순서 변경은 타임라인에도 반영할 수 있지만, 사용자가 이미 손본 컷·전환을 덮어쓸 때는 변경 내용을 보여준다. 두 화면은 같은 샷 ID를 사용하며 서로 독립된 복사본으로 방치하지 않는다.

모션과 타이포의 공통 표현은 다음 정보를 담는다.

- 컴포지션 크기, 시간 기준, 총 길이, 레이어 순서와 앵커.
- 레이어 종류, 연결 소재, 정확한 텍스트·글꼴·색상·정렬.
- 레이어의 시작·종료와 위치·크기·회전·투명도 등의 키프레임.
- easing, 마스크·전환, 비트 또는 음성 타이밍과의 관계.
- 렌더러 전용 기능과 해당 기능이 필요한 실행 도구.

초 단위 표시와 별개로 내부 편집 시간은 정수 tick 또는 유리수 시간 기준을 사용해 프레임 반올림 오차를 제한한다. 생성 모델의 영상 길이·fps와 최종 편집 프로젝트의 값은 따로 기록한다.

AE, FFmpeg 등 모든 도구가 같은 표현을 전부 처리한다고 가정하지 않는다. 공통 기능과 도구 전용 기능을 표시하고, 전용 효과를 다른 도구로 바꿀 때 변환 가능 범위를 안내한다. 정확한 한국어 카피는 편집 가능한 텍스트 레이어를 우선 사용한다. AI 생성 영상에 포함된 글자는 정확성이 확인된 것으로 취급하지 않는다.

노드 프리뷰는 빠른 확인용 출력일 수 있다. 최종 결과와 같은 엔진으로 만든 프리뷰인지 표시하고, 최종 출력은 파일을 실제로 열어 재생 길이·화면·소리를 확인한 후 완료로 기록한다.

## 9. 연결 관리와 MCP 등록

### 9.1 연결 관리 화면

`연결 추가 → 방식과 인증 입력 → 연결 확인 → 기능 목록 읽기 → 사용할 기능 선택 → 저장`

| 연결 종류 | 등록 항목 |
| --- | --- |
| 로컬 MCP | 실행 파일, 분리된 인수 배열, 작업 폴더, 필요한 환경변수 참조 |
| 원격 MCP | 서버 URL, 지원 전송 방식, 해당 서버가 요구하는 인증 |
| ChatGPT OAuth | 브라우저 로그인, 계정 식별, 토큰 갱신, 연결된 모델/기능과 사용 한도 |
| 서비스 API | 공급자, 모델 목록/설정, API 인증 참조 |
| Modal | 기존 프로필 연결, 배포 앱·함수 또는 클래스, 등록 워크플로 |
| 로컬 제작 도구 | 실행 파일 또는 브리지, 버전, 지원 기능, 프로젝트·렌더 방식 |

MCP는 로컬 stdio와 원격 Streamable HTTP를 우선 대상으로 한다. 구형 전송 방식은 실제 연결 대상이 요구할 때 지원 여부를 결정한다. 구체적인 SDK와 프로토콜 버전은 구현 시 대상 서버와 호환성을 확인해 고정한다.

연결 목록에는 이름, 종류, 연결 상태, 제공 도구 수, 마지막 확인 시각, 인증 만료/연결 오류를 표시한다. `저장됨`, `서버 연결됨`, `도구 확인됨`, `실행 검증됨`을 구분한다. 연결 테스트는 기본적으로 초기화와 기능 조회이며, 유료 생성이나 기존 AE 프로젝트 변경을 포함하지 않는다.

### 9.2 MCP 도구를 노드에 노출하는 방식

도구의 이름·설명·입력 형식·제공되는 출력 형식을 읽어 카탈로그에 보관한다. 도구 호출 중심으로 시작하고, resources/prompts를 제공하는 서버는 실제 작업에서 필요한 항목을 추가로 노출한다.

자주 쓰는 기능은 이미지 생성·영상 생성·디자인·모션 노드의 실행 도구로 연결한다. 아직 전용 어댑터가 없는 도구는 `도구 실행` 노드에서 입력 형식에 맞는 폼 또는 구조화된 편집기로 사용할 수 있게 한다. 도구 목록 조회만으로 의미 있는 미디어 입출력 매핑이 완성되지는 않는다.

도구 입력의 파일 경로·URL·첨부 방식과 결과의 파일·URL·프로젝트 형식을 어댑터가 해석한다. 출력 형식이 불명확하면 원본 결과로 보관하고, 확인된 매핑이 있을 때만 다음 이미지·영상 포트로 연결한다.

카탈로그가 바뀌면 도구별 입력 형식의 변경을 감지한다. 기존 노드를 최신 형식으로 조용히 바꾸지 않고 호환 상태와 수정할 입력을 표시한다. 저장된 프로젝트에는 사용 도구와 형식 버전을 기록한다.

### 9.3 연결과 인증의 경계

MCP 등록은 앱이 서버에 접근할 수 있을 때 성립한다. 현재 개발 대화에서 사용할 수 있는 커넥터나 GPT 이미지 도구가 이 앱에 자동으로 제공되는 것은 아니다. Higgsfield도 앱에서 사용할 수 있는 서버 주소·인증·호출 권한을 별도로 확인해야 한다. 사용 가능한 접속 방법이 확인되지 않으면 연결 대기로 표시한다.

비밀값은 OS의 안전한 저장소에 두고 DB에는 참조만 저장한다. 인증값을 채팅, 프롬프트, 실행 로그, 프로젝트 내보내기에 포함하지 않는다. 로컬 서버는 실행 파일과 인수 배열로 기동하며 문자열을 조합해 셸 명령으로 실행하지 않는다. 서버 등록과 최초 실행은 화면에서 구분한다.

채팅에서 사용할 도구는 사용자가 활성화한 범위로 제한한다. 서버가 반환한 텍스트는 작업 데이터로 취급하며 앱의 권한·인증·실행 규칙을 바꾸는 지시로 사용하지 않는다.

### 9.4 ChatGPT OAuth: 참고 저장소와 재사용 범위

사용자 지정 참고 저장소는 [coseung2/oauth-collect](https://github.com/coseung2/oauth-collect)다. 2026-09-27에 `main`의 커밋 `fd42ba145356a9c44e567c8f847088459bc71e8c`를 기준으로 README와 ChatGPT 인증·공통 인증·자격증명·공급자 등록 코드를 확인했다. 실제 계정 로그인이나 토큰 발급은 수행하지 않았다.

| 저장소에서 확인한 구현 | 앱 설계에 반영할 내용 |
| --- | --- |
| `ChatGPTOAuthFlow`, `loginChatGPT` | Authorization Code + PKCE(S256), 임의 state, 코드 교환을 ChatGPT 인증 어댑터의 기준으로 사용 |
| 고정 redirect URI | `http://localhost:1455/auth/callback`을 사용. 포트가 사용 중이면 임의 포트로 바꾸지 않고 충돌을 표시 |
| `forceLogin` | 다른 계정을 추가할 때 브라우저 세션 재사용 대신 새 로그인을 요청할 수 있도록 제공 |
| `refreshChatGPTToken` | form-encoded refresh 요청과 응답 자격증명 갱신 |
| `ensureFresh`, `needsRefresh` | 요청 직전 만료 여유를 확인하는 갱신 방식. 참고 구현은 기본 60초 여유를 사용 |
| ChatGPT `refreshPolicy: lazy-only` | 사용하지 않는 계정에 주기적으로 갱신 트래픽을 보내지 않음 |
| `access`, `refresh`, `expires`, `accountId`, `email` | 토큰과 표시용 계정 정보를 분리해 저장 |
| 런타임 독립 TypeScript | 브라우저 열기, HTTP 콜백 서버, 토큰 저장, 모델 추론은 호스트 앱이 구현 |

패키지는 현재 private 참조 구현이므로 설치 가능한 공개 npm 패키지로 전제하지 않는다. 필요한 ChatGPT 관련 코드와 출처·MIT 라이선스를 고정 버전으로 가져오거나, 동등한 네이티브 구현의 기준으로 사용한다. 다른 일곱 공급자의 인증 추가는 별도 범위다.

기본 구현 제안은 Tauri의 신뢰된 백엔드에서 인증 어댑터와 콜백을 관리하는 것이다. 기존 Rust 코어에 이식하면 이 기능만을 위해 JavaScript 런타임을 배포할 필요가 없다. TypeScript를 직접 재사용하기로 결정하면 신뢰된 별도 실행부에 두고, 렌더러 WebView에는 토큰을 전달하지 않는다. 두 방식 중 하나를 구현 시 확정하고 같은 인증 계약으로 검증한다.

### 9.5 로그인 화면과 동작

연결 관리에 `ChatGPT로 로그인`을 제공한다. 로그인 후에는 계정 이름, 확인 가능한 workspace/plan, 로그인 상태, 사용 가능한 기능, 마지막 확인 시각을 보여준다. 모델 선택 목록은 실제 호출 경로에서 확인한 목록을 사용한다.

1. 앱 코어에서 로그인 시도 ID와 PKCE·state를 만들고, 콜백 리스너가 준비됐는지 확인한다.
2. 기본 브라우저에서 인증 URL을 연다. 비밀번호 입력은 인증 제공자의 화면에서 진행한다.
3. 앱은 loopback의 정확한 callback path에서 완료 URL을 받는다. 현재 로그인 시도의 state와 일치하는 응답 한 번만 수락한다.
4. authorization code를 교환하고, 토큰은 안전한 저장소에 저장한다. UI에는 표시용 계정 정보와 상태만 전달한다.
5. 선택한 모델 실행 경로에서 계정·모델·첨부·도구 호출 기능을 확인한다. 로그인 완료와 기능 확인 결과를 따로 표시한다.
6. 프로젝트와 노드에서 해당 GPT 연결을 선택해 기획·프롬프트·참조 해석에 사용한다.

브라우저를 닫았거나 로그인 시간이 초과되면 리스너와 메모리의 임시 인증 정보를 정리하고 다시 로그인할 수 있게 한다. 동시에 여러 로그인 시도를 열어 state나 콜백을 섞지 않는다. 포트 1455가 다른 프로그램에 사용 중이면 그 프로세스를 종료하거나 콜백을 가로채지 않고 충돌 원인을 표시한다.

참고 라이브러리는 raw code 입력도 허용하지만 앱의 기본 경로는 state가 포함된 전체 callback URL만 수락한다. 참고 코드의 `AbortSignal` 타입 존재만으로 요청 취소·timeout이 완성됐다고 보지 않고, 브라우저 대기·콜백·교환 요청의 종료 동작을 호스트에서 구현한다.

### 9.6 토큰·계정 수명 관리

- `provider + accountId`를 계정 식별 기준으로 삼고, 이메일은 표시 정보로 사용한다. 토큰 payload에서 읽은 claim을 실제 계정 조회·호출 성공과 동일하게 취급하지 않는다.
- 요청 직전에 만료 여유를 확인한다. 같은 계정의 여러 노드가 동시에 요청해도 refresh는 한 번만 수행하고 갱신 결과를 공유한다.
- 회전한 refresh token은 원자적으로 교체한다. 새 응답이 refresh token을 생략했을 때 기존의 유효한 값을 빈 문자열로 덮어쓰지 않는다. 계정 식별 정보도 응답 생략과 계정 변경을 구분한다.
- 갱신 응답이 늦게 도착해도 로그아웃하거나 삭제한 계정이 다시 살아나지 않도록 계정 버전과 로그인 시도를 확인한다.
- 인증 실패·재로그인 필요와 네트워크 일시 오류를 구분한다. 무한 갱신 루프나 계정 자동 전환으로 작업을 반복하지 않는다.
- 연결 해제 시 앱이 보관한 해당 계정 토큰과 런타임 인증 상태를 제거한다. 원격 세션 철회는 실제 지원되는 동작일 때 별도 처리한다.

참고 구현에는 고정 client ID·scope·엔드포인트가 포함돼 있다. 구현 시 해당 OAuth 등록과 배포 앱의 사용 가능 범위를 확인하고, 공급자 변경은 인증 어댑터 버전으로 관리한다. connector 관련 scope가 있다는 사실만으로 Higgsfield나 다른 MCP 연결까지 자동으로 이전된다고 가정하지 않는다.

### 9.7 OAuth 인증과 GPT 모델 실행 연결

`oauth-collect`가 반환하는 자격증명을 받을 모델 실행 어댑터가 추가로 필요하다. 설계상 첫 검토 경로는 **호스트가 OAuth를 관리하고 Codex App Server에 외부 토큰을 전달하는 방식**이다. 공식 문서의 `chatgptAuthTokens` 모드는 이 용도이며 현재 실험적 기능으로 명시돼 있으므로, 채택 시 호환되는 런타임 버전과 호출 계약을 고정한다.

공식 문서에서 확인한 연결 지점은 다음과 같다.

- `account/login/start`의 외부 토큰 모드: access token, ChatGPT account ID와 선택적 plan 정보를 전달한다.
- `account/chatgptAuthTokens/refresh`: 런타임이 새 토큰을 요구할 때 앱의 계정별 갱신 경로로 처리한다.
- `account/read`, `account/updated`: 실제 계정과 로그인 상태를 반영한다.
- `account/rateLimits/read`, `account/usage/read`: 반환 가능한 한도와 사용 정보를 조회한다. 제공되지 않은 값은 추정해 채우지 않는다.

이 경로를 도입하면 앱이 OAuth 토큰의 소유자이고 런타임은 소비자다. 같은 계정에 대해 앱과 런타임이 각각 refresh token을 관리하지 않도록 인증 소유자를 하나로 정한다. 여러 계정은 런타임/세션도 계정별로 격리하고 실행 중 계정을 바꾸지 않는다. 현재 개발에 사용하는 Codex 로그인 저장소를 읽거나 공유하는 방식에 의존하지 않는다.

런타임의 도구 호출은 앱에서 등록·활성화한 노드 기능으로 연결한다. 모델이 이미지·영상 생성 도구를 직접 실행한 경우에도 앱 작업 ID와 결과 소재를 기록한다. 앱 코어와 모델 런타임이 같은 작업을 이중 실행하지 않게 실행 소유자를 정한다.

ChatGPT OAuth 연결과 OpenAI Platform API 키 연결은 별도 계정 유형으로 유지한다. 공식 인증 문서는 구독 로그인과 API 사용량 결제를 구분한다. OAuth 토큰을 임의의 Platform API에 전달하거나, OAuth 실패 시 API 키로 자동 전환하지 않는다.

**GPT 이미지 생성은 OAuth 로그인만으로 가능하다고 확정하지 않는다.** 선택한 실행 경로에서 이미지 생성 도구가 제공되고 결과 파일을 앱에 받을 수 있는지 확인한다. 지원되면 같은 ChatGPT 연결의 기능으로 노출하고, 지원되지 않으면 별도로 등록한 이미지 API 연결을 선택할 수 있게 한다. 동영상 이해·MCP 호출도 동일하게 기능별로 확인한다.

### 10.1 Modal의 ComfyUI 워크플로

등록된 ComfyUI 워크플로 하나를 캔버스의 작업 하나로 감싼다. 앱 노드 연결과 ComfyUI 내부 노드 그래프는 별도로 관리한다. 필요할 때 원본 워크플로 정보나 외부 편집기로 이동할 수 있게 한다.

워크플로 등록 정보에는 ID·이름·버전, 배포 앱/함수, 원본 파일 hash, 입력·출력 형식, 입력에 대응하는 ComfyUI 노드 ID/필드, 기본값·허용 범위, 필요 모델과 custom node 버전을 둔다. 프롬프트·이미지·영상·seed·길이 등의 변경은 명시된 필드에만 적용한다.

API 실행 형식의 워크플로를 우선한다. 편집기 형식의 JSON만 있는 경우 해당 워크플로에서 검증한 변환 과정을 사용한다. UI JSON 업로드만으로 의존 모델 설치와 배포까지 완료됐다고 표시하지 않는다.

실행 시 입력 파일을 업로드하고 원격 호출을 시작한 뒤, 실제 조회 가능한 호출 ID와 ComfyUI prompt ID를 저장한다. 중간 진행 정보, 결과 경로, 오류를 앱 작업에 연결한다. 결과 파일이 준비되면 내려받아 소재로 등록한다. 컨테이너 시작·모델 준비·추론·결과 수신을 가능한 범위에서 구별한다.

최초 연결은 기존 H3 워크플로 하나로 검증하고, 서로 다른 입출력 형식의 두 번째 워크플로를 등록해 범용화 정도를 확인한다. 다중 입력과 취소·재접속은 각 배포의 실제 지원 여부를 따른다.

### 10.2 After Effects

AE 연결은 앱 설치 확인, MCP/브리지 연결, 도구 조회, 샘플 프로젝트 작업, 렌더 결과 확인의 단계를 거친다. 연결 이름만으로 AE 전체 기능이 지원된다고 표시하지 않는다.

작업은 앱 프로젝트에 귀속된 AE 프로젝트/컴포지션을 사용한다. AE에서 사용자가 열어둔 다른 작업에 대한 변경이 섞이지 않도록 대상 프로젝트와 컴포지션 ID를 실행 입력에 고정한다. 같은 AE 세션의 변경 작업은 기본적으로 순차 실행한다.

텍스트·로고·소재·키프레임을 전달해 편집 가능한 프로젝트를 만들고, 렌더가 지원되면 출력 파일까지 받는다. 프로젝트 생성만 가능하면 `프로젝트 준비됨`으로 끝내고 다음 사용자 행동을 제공한다. 파일 생성과 렌더 완료는 다른 결과 종류다.

## 11. 실행 아키텍처

```text
React 작업 공간
  캔버스 · 스토리보드 · 채팅 · 타임라인 · 연결 관리
                         │ 명령 / 이벤트
Tauri / Rust 앱 코어
  프로젝트 저장 · 자료형 검증 · 실행 계획 · 작업 상태 · 자격증명 참조
                         │
  ┌──────────────────────┼──────────────────────────┐
  │                      │                          │
AI / 서비스 어댑터     MCP 클라이언트             기존 Python 실행부
  대화 · 이미지 API      로컬/원격 서버              Modal · Comfy · 렌더러
  │                      │                          │
  └──────────────────────┼──────────────────────────┘
                         │
                결과 수신 · 소재 등록 · 실행 이력
                         │
                  SQLite + 로컬 미디어 저장
```

React는 편집 상태와 화면 표시를 담당한다. 저장 상태와 작업 실행의 기준은 앱 코어에 둔다. 외부 자격증명과 로컬 프로세스 관리는 네이티브 측에서 수행한다. 현재 Python 실행부는 Modal과 렌더러에 계속 활용한다. MCP·AI 클라이언트의 구체적인 언어/SDK 선택은 호환성 확인 후 정하되, 프런트엔드에 원격 호출을 직접 흩어놓지 않는다.

ChatGPT 연결에는 앱 코어의 OAuth 세션 관리자, loopback 콜백, 비밀 저장소, 계정별 갱신 잠금이 추가된다. AI 어댑터가 요청할 때 필요한 계정의 유효한 access token을 제공한다. Codex App Server 경로를 채택하면 AI 어댑터 아래에 계정별 런타임 프로세스와 이벤트 변환을 두고, 프로젝트·실행 이력의 기준은 계속 앱 코어에 둔다.

대화 AI가 제안하는 작업도 버튼 실행과 같은 입력 검증·실행 경로를 통과한다. 공급자마다 독립된 별도 작업 큐를 화면에 만드는 대신 공통 실행 상태로 묶고, 공급자 고유 상태는 상세 정보로 남긴다.

### 11.1 실행 어댑터 계약

어댑터는 지원 기능 조회, 입력 검증, 입력 파일 준비, 실행 시작, 상태 확인, 결과 수신을 제공한다. 취소·재접속·진행률·비용 추정은 지원 여부를 명시한다. 모든 어댑터가 이 기능을 갖췄다고 전제하지 않는다.

공통 입력은 노드 실행 ID, 연결 ID, 작업 종류, 입력 소재와 역할, 프롬프트/구조화된 설정, 선택 모델/워크플로 버전이다. 공통 결과는 원격 실행 ID(있을 때), 소재 목록, 프로젝트 파일, 원본 응답 참조, 비용 정보다.

장시간 걸리는 MCP 호출은 서버의 실행 방식에 따라 처리한다. 일반 동기 호출만 제공하는 서버에서는 앱 재시작 후 이어받기가 불가능할 수 있다. 원격 task ID·상태 조회 기능이 있는 경우에만 재접속을 지원한다고 표시한다.

## 12. 실행·재실행·복구 규칙

사용자가 실행을 시작하면 앱은 실행 대상과 필요한 상위 입력을 계산하고, 자료형·누락 입력·도구 연결·지원 옵션을 검사한다. 준비된 입력과 선택 설정의 스냅샷을 저장한 뒤 작업을 시작한다. 이미 완료된 입력 결과는 다시 사용하고 필요한 실행만 수행한다.

### 12.1 상태

| 상태 | 뜻 |
| --- | --- |
| 편집 중 | 설정을 구성하는 단계 |
| 입력 필요 / 선택 필요 | 필수 파일·설정 또는 후보 선택이 없어 진행할 수 없음 |
| 준비됨 | 입력과 연결 검사를 통과함 |
| 대기 | 실행 자원 또는 상위 결과를 기다림 |
| 실행 중 | 요청 전달·생성·렌더·결과 수신 중 |
| 완료 | 기대한 결과를 수신·확인하고 소재로 등록함 |
| 프로젝트 준비됨 | 외부 도구에서 이어갈 파일을 준비함 |
| 실패 | 확인된 실패와 다시 시도 가능한 범위를 기록함 |
| 취소 요청됨 | 중단을 요청했으나 원격 중단은 아직 확인되지 않음 |
| 취소됨 | 해당 실행의 취소가 확인됨 |
| 상태 확인 필요 | 연결이 끊겨 원격 작업의 완료·실패·취소를 아직 판단할 수 없음 |

`입력 변경됨`은 완료 결과에 추가되는 표시이며 과거 실행의 성공 상태를 덮어쓰지 않는다. 진행률을 받지 못하면 단계와 경과 시간만 보여주고 임의의 백분율을 만들지 않는다.

### 12.2 재실행과 중복 방지

- 실행마다 별도 ID와 시도 번호를 발급하고, 입력 버전·모델·워크플로·seed·참조 파일 hash를 기록한다.
- 실행 버튼 연속 클릭과 통신 재시도로 같은 작업이 중복 제출되지 않도록 제출 기록을 보존한다.
- 제출 응답이 끊긴 경우 원격 작업 조회나 공급자의 중복 방지 기능을 먼저 사용한다. 실행 여부가 불명확하면 자동으로 새 유료 작업을 제출하지 않는다.
- 같은 입력의 기존 결과 재사용과 새 변주 생성은 다른 행동이다. 사용자가 새 변주를 요청하면 새 실행으로 남긴다.
- 생성은 성공했고 다운로드만 실패했다면 결과 수신부터 다시 시도한다.
- 종료된 실행에 늦은 이벤트가 도착해도 다른 실행이나 최신 후보를 덮어쓰지 않는다. 이벤트 ID/순서와 실행 ID를 확인한다.

### 12.3 취소와 앱 재시작

앱을 다시 열면 미완료 실행의 실제 원격 ID로 상태를 확인한다. 이어받을 수 없는 공급자는 그 한계를 표시한다. 로컬 관찰 중단, 프로세스 종료, 원격 생성 취소를 같은 의미로 기록하지 않는다.

취소 요청 시 이미 시작한 외부 작업은 비용이 발생할 수 있다. 이후 도착한 결과가 있으면 취소 상태와 별도로 결과 보관 여부를 기록한다. 후보 선택 대기 중인 흐름은 앱을 닫아도 유지하고, 선택 후 남은 단계부터 이어간다.

병렬 실행 한도는 공급자·계정·Modal 워크플로·로컬 제작 도구별로 둔다. AE 같은 상태가 있는 로컬 도구는 동일 프로젝트를 동시에 변경하지 않게 한다.

## 13. 데이터와 파일 저장

### 13.1 제안하는 저장 단위

기존 계정·작업 테이블을 보존하면서 다음 개념을 추가한다. 표의 이름은 제안이며, 실제 마이그레이션 설계에서 확정한다.

| 저장 단위 | 핵심 내용 |
| --- | --- |
| `projects` | 이름, 제작 설정, 소재 루트, 활성 문서 버전 |
| `project_revisions` | 버전이 있는 노드·연결·샷·타임라인 JSON, 편집/저장 시각 |
| `assets` | 소재 ID, 종류, hash, 크기·길이·해상도, 출처, 생성 실행 ID |
| `asset_locations` | 로컬 파일, 공급자 파일 ID/URL, 만료·다운로드 상태 |
| `conversations`, `messages` | 프로젝트/노드 범위, 메시지, 도구 호출, 소재 참조, 맥락 정보 |
| `connections` | 연결 종류, 비밀값 없는 설정, 인증 참조, 상태 |
| `provider_accounts` | 연결 ID, 공급자 계정 ID, 표시명, 인증 방식, 만료 시각, 자격증명 참조·버전, 재로그인 상태 |
| `capability_snapshots` | 도구 목록, 입력 형식, 지원 기능, 버전, 확인 시각 |
| `workflow_definitions` | Comfy 등 등록 워크플로 버전, 입력 매핑, 실행 위치 |
| `runs` | 한 번의 흐름 실행, 고정된 프로젝트 버전, 실행 대상과 상태 |
| `node_runs` | 노드별 실행 시도, 입력 스냅샷, 원격 ID, 상태·결과·오류 |
| 실행 이벤트·비용 | 기존 `job_events`·`usage_records`의 보존/확장 또는 연결 테이블 |

초기에는 캔버스 편집 문서를 하나의 버전 있는 JSON으로 저장해 노드·연결·샷을 함께 복원한다. 실행·소재·비용처럼 독립 조회가 필요한 정보는 별도 테이블로 둔다. 큰 파일과 base64 미디어는 문서 JSON이나 채팅 행에 넣지 않는다.

`project_id`, `node_id`, `shot_id`, `run_id`, `node_run_id`, `asset_id`, `connection_id`를 구분한다. 원격 실행 ID는 공급자·연결·로컬 실행 ID와 함께 저장한다. 프롬프트·참조·결과의 출처를 실행 이력에서 역으로 확인할 수 있어야 한다.

### 13.2 소재 파일

프로젝트별 원본, 생성 결과, 썸네일/프록시, 내보내기 파일을 구분한다. 가져오기는 프로젝트 폴더로 복사를 기본으로 하고, 원본 위치 참조는 선택 옵션으로 제공한다. 원본이 이동되면 다시 연결할 수 있게 한다.

원본 파일은 보존하고 프리뷰용 작은 영상을 별도로 만들 수 있다. 다운로드는 임시 파일에 받은 뒤 완료된 파일만 소재로 등록한다. 파일 hash로 동일 소재를 식별하되 서로 다른 후보 선택이나 편집 이력을 합치지 않는다.

원격 파일 URL이 만료될 수 있으므로 가능한 경우 완료 결과를 로컬에 보관한다. 로컬 경로를 원격 MCP가 바로 읽을 수 있다고 가정하지 않는다. 공급자가 지원하는 업로드 방식이나 명시적으로 준비한 접근 URL을 사용하고 전송 상태를 보여준다.

프로젝트 내보내기에는 버전 있는 제작 문서, 선택 소재, 연결 요구사항을 포함한다. 인증값은 제외한다. 가져오기 시 없는 연결·폰트·워크플로·소재를 찾아 다시 연결하도록 표시한다.

## 14. 비용과 사용량

현재 계정·작업 사용량 구조를 전체 제작 실행으로 확장한다. 프로젝트, 노드, 실행 시도, 연결 계정에 비용을 연결한다. 영상 생성뿐 아니라 대화, 이미지 생성, 렌더도 기록 가능한 범위에서 포함한다.

금액은 `추정`, `실제 확인`, `미확인`, `반영 대기`를 구분한다. 값이 없다는 이유로 0으로 표시하지 않는다. 취소·실패한 실행도 비용 확인 대상이다. 공급자 합계와 개별 작업 비용을 함께 더해 중복 계산하지 않는다.

ChatGPT OAuth는 구독 계정의 사용 한도·갱신 시각과 실제 조회 가능한 사용 정보를 표시한다. 이를 API 단가로 환산한 확정 비용이나 무제한 무료 사용으로 표현하지 않는다. API 키 연결의 사용량 결제 기록은 별도로 관리한다.

실행 전에 확인 가능한 예상 비용과 후보 수를 보여준다. 비용을 제공하지 않는 도구는 미확인으로 표시한다. 계정/프로젝트 예산을 적용할 수 있게 하되 추정 기반 예산과 실제 서비스 잔액을 구분한다.

## 15. 대표 제작 시나리오

### 15.1 제품 광고

1. 프로젝트를 만들고 제품 이미지, 로고, 참고 영상을 넣는다.
2. 브리프에서 확인된 제품 정보·필수 문구·목표 길이를 지정한다.
3. 무드보드 대화로 색감·소재·카메라 방향을 정한다.
4. 스토리보드에서 hook, 제품 장면, 마무리 등 필요한 샷을 구성한다.
5. 샷별로 GPT 이미지 또는 연결된 디자인 도구로 키비주얼을 만들고 후보를 고른다.
6. 선택한 이미지를 Higgsfield 또는 Modal 영상 생성 노드에 연결한다.
7. 원하는 클립을 고정하고 정확한 광고 문구를 키네틱 타이포 노드에 입력한다.
8. AE 또는 지원 렌더러에서 타이포·모션을 만들고, 사운드는 코드 제작 또는 YuE2 생성으로 조달해 편집·합성 노드에서 결합한다.
9. 프리뷰를 확인하고 최종 영상을 출력한다. 수정할 때는 해당 샷 또는 타이포만 다시 실행한다.

### 15.2 기존 Modal 워크플로 활용

1. 연결 관리에서 기존 Modal 프로필을 선택한다.
2. 배포된 워크플로를 등록하고 프롬프트·참조·seed 등의 입력을 매핑한다.
3. 캔버스에서 Comfy 워크플로 노드를 추가해 소재와 프롬프트를 연결한다.
4. 실행한 결과를 후보로 비교하고 다음 영상·편집 노드에 연결한다.
5. 워크플로를 갱신하면 새 버전으로 등록하고 기존 프로젝트는 이전 버전을 계속 식별한다.

### 15.3 새 MCP 추가

1. 서버 실행 정보 또는 URL과 인증을 등록한다.
2. 연결 테스트로 도구 목록과 입력 형식을 읽는다.
3. 필요한 도구를 활성화하고 범용 도구 노드에서 입력을 확인한다.
4. 실제 결과 형식에 맞는 어댑터가 있으면 이미지·영상·모션 노드에서도 선택한다.
5. 호출 결과를 확인한 뒤 해당 연결의 실행 검증 상태를 갱신한다.

## 16. 구현 순서와 완료 기준

| 단계 | 구현 범위 | 완료 기준 |
| --- | --- | --- |
| 0. 공통 형식 | 프로젝트·노드·포트·소재·실행·연결 형식과 기존 데이터 매핑 | 샘플 프로젝트의 저장·복원과 기존 이력 보존 전략이 명확함 |
| 1. 제작 화면 | 캔버스, 노드 추가/연결, 무드보드·스토리보드, 우측 편집/첨부, 저장/되돌리기 | 실제 이미지·영상으로 노드 편집·연결·재시작 복원이 동작함. 모의 결과는 명시함 |
| 2. 기존 실행 연결 | H3 워크플로 하나, 결과 등록·후보 선택, 기존 로컬 편집/렌더 | 소재 입력부터 실제 결과 파일 재생까지 한 제작 흐름이 완성됨 |
| 3. AI·MCP 확장 | ChatGPT OAuth·갱신·모델 실행 연결, GPT 이미지 지원 확인, MCP 등록·조회·도구 노드, Higgsfield 어댑터 | 로그인·재시작·토큰 갱신 후 같은 계정으로 대화하고, 첨부·생성 결과가 후속 노드로 전달됨 |
| 4. 모션 제작 | AE 연결, 키네틱 타이포·모션 형식, 타임라인, 추가 Comfy 워크플로 | 정확한 문구를 편집·렌더하고 서로 다른 워크플로를 같은 캔버스에서 사용함 |
| 5. 작업 안정화 | 재접속·취소·중복 방지·비용 귀속·프로젝트 내보내기·템플릿 | 실패/재시작 상황에서도 이력과 선택 결과를 보존하고 필요한 단계부터 복구함 |

저장과 실행 ID·중복 방지의 기본 계약은 단계 0부터 적용한다. 단계 5는 이 기능의 도입 시점이 아니라 여러 공급자에서의 검증을 마무리하는 단계다. 재접속이 필요한 공급자의 실제 원격 ID 확보는 해당 공급자 연결 단계의 완료 조건에 포함한다.

첫 화면 검토는 단계 1에서 진행한다. 전체 도구를 연결하기 전에 실제 레퍼런스 이미지·영상으로 캔버스 밀도, 노드 편집, 샷 선택과 채팅 첨부 동선을 확인한다. 이후 작동하는 한 제작 흐름에 연결 도구를 늘린다.

### 16.2 구현 현황 (2026-09-27)

0~5단계의 기능을 구현했다. 5단계의 "필요한 단계부터 복구"는 로컬 렌더 중단 복구와 취소 뒤 결과 다시 받기까지 확인했고, 공급자가 상태 조회를 제공하지 않는 원격 취소 확인은 한계로 남는다. 아래 표의 남은 항목과 16.3의 한계를 함께 봐야 한다. 검증한 범위와 아직 확인하지 않은 범위를 구분해 기록한다. 같은 날 오후 갱신이며, 4~5단계 항목은 네이티브 앱에서 실제로 실행해 확인한 결과다.

| 추가 Comfy 워크플로와 워크플로 등록 화면(4단계) | 구현 | 연결 관리 화면에서 워크플로 등록·삭제, Comfy 노드의 워크플로 선택이 등록 목록과 선언된 입출력을 표시. 같은 캔버스에서 H3와 YuE2를 선택할 수 있고, YuE2 워크플로로 실제 음악 생성 완료(FLAC 48kHz 스테레오 102초) |
| 취소 요청(5단계) | 구현 | 로컬 렌더에 중단을 요청하면 `cancel_requested`로 남고, 취소 뒤 도착한 결과는 완료로 기록하면서 "중단을 요청한 뒤 도착한 결과" 사실을 함께 남긴다(Rust 테스트 + 네이티브 화면 확인). worker로 취소 메시지를 보내는 경로는 코드·단위 테스트로 확인했고, 실제 Modal 작업 취소 통합은 미검증 |
| 취소 뒤 결과 수신 복구(5단계) | 구현 | 네이티브 앱에서 YuE2 음악 실행을 중단 요청 → 원격 생성이 끝나며 원격 경로가 기록됨 → 화면의 `원격 결과 다시 받기`로 같은 결과를 다시 내려받아 완료(54초 FLAC, 생성 재실행 없음)까지 확인. 실제 H3 영상에서의 같은 흐름은 미검증 |
| 중복 제출 방지(5단계) | 구현 | 같은 입력·seed의 제출은 30초 안에 거부하고 다른 seed·입력은 새 변주로 허용. Rust 테스트와 네이티브 화면에서 거부 안내 확인 |
| 비용 귀속(5단계) | 구현 | 프로젝트별 실행 비용 요약이 실행마다 `확인됨`/`반영 대기`/`미확인`을 구분하고 값이 없으면 0이 아니라 null로 남긴다. 네이티브 화면에서 확인. Modal 청구서가 실행별 비용을 주지 않는 동안에는 `미확인`으로 표시됨 |
| 실행 계정 선택(5단계) | 구현 | 영상·음악·Comfy 노드에서 Modal 계정을 고르면 프로젝트 문서(`config.profileId`)에 저장되고 실행 요청(`profile_id`)으로 전달된다. 앱 화면에서 선택·저장을 확인했고, Rust 테스트로 요청의 계정이 작업 기록(`jobs.modal_profile_id`)까지 전달되는 것을 확인했다. 등록된 계정이 하나뿐이라 두 계정 실실행은 아직 확인하지 않았다 |
| 도구 노드 호환성 검사 | 구현 | 연결에서 사라진 도구·중지된 도구·필수 입력 누락·JSON 형식 오류·객체가 아닌 입력을 실행 전에 알리고 호출하지 않는다. 연결 테스트가 서버 목록에 없는 도구를 캐시에서 지우고(Rust 테스트), 앱 화면에서 필수 입력 누락 시 경고가 뜨고 실행이 거부되며 실행 기록이 생기지 않는 것을 확인 |
| 프로젝트 내보내기·가져오기(5단계) | 구현 | 네이티브 앱에서 실제 소재 39개(구성 JSON 포함)를 폴더로 내보내고 다시 가져와 새 프로젝트가 만들어지는 것을 확인. 가져온 프로젝트의 소재와 구성 JSON이 참조하는 클립·오디오가 모두 새 프로젝트 폴더로 복사되어 내보낸 폴더 없이도 렌더가 이어진다(구성 9개·클립 9개·오디오 9개 확인). manifest에 `secrets_included: false`, 누락 글꼴·워크플로·연결 안내를 표시. 폴더 선택 대화상자 자체는 수동 확인 필요 |
| 노드 그룹 템플릿(5단계) | 구현 | 프로젝트 검사 패널에서 선택한 노드를 템플릿으로 저장하고 캔버스에 다시 놓아 노드 수가 늘어나는 것을 확인 |
| 연결 관리 화면과 MCP 클라이언트(stdio·Streamable HTTP) | 구현 | Rust 테스트로 실제 stdio 서버와 initialize/tools/list/tools/call·타임아웃 확인, 네이티브 화면에서 등록·연결 테스트·도구 4개 확인 |
| 도구 실행 노드 → MCP 호출 | 구현 | 네이티브 앱에서 `write_frame` 실행 → 원본 JSON 소재 등록 → 결과 파일을 확인 후 이미지 소재로 등록 |
| ChatGPT OAuth 로그인·토큰 갱신 | 구현(목 서버 + 실계정) | 참고 커밋의 client_id·scope·고정 콜백(1455) 기준. PKCE S256·state 1회 수락·포트 충돌·시간 초과·취소를 Rust 테스트로 확인하고, 목 OAuth 서버로 네이티브 화면에서 로그인 완료·계정 표시·불필요한 갱신 안 함까지 확인. 실제 계정 로그인은 아래 "실제 ChatGPT 로그인과 실모델 대화" 행에서 확인 |

3단계 검증에 쓴 목 서버는 `tools/test_oauth_server.py`(인증·토큰)와 `tools/test_app_server.py`(app-server 프로토콜)이며, 실제 서비스가 아니다. 실계정 검증과 목 검증을 같은 것으로 보고하지 않는다.

브라우저 미리보기 검증은 Tauri 앱 검증과 별개다. 네이티브 앱은 빌드·실행과 DB 마이그레이션까지 확인했고, 4~5단계의 화면 조작은 앱 창에서 실제로 확인했다. 앱 창에서 아직 확인하지 않은 것은 네이티브 파일·폴더 선택 대화상자다.

실행 검증에 사용한 실제 결과 파일은 로컬 데이터 루트에 보관했고, 실행 기록은 앱 DB의 `studio_runs`·`jobs` 행과 프로젝트 문서의 후보 소재 목록에 남아 있다.

4~5단계 검증은 네이티브 앱 창에서 실행했고, 화면 조작은 WebView2 원격 디버깅 포트로 확인했다. 실제 외부 실행은 Modal H3 영상 생성, Modal YuE2 음악 생성, 로컬 FFmpeg 렌더, 실제 ChatGPT 로그인·모델 대화·첨부 전달, After Effects 2021 프로젝트 생성이다. Higgsfield 등 실제 MCP 서버 연결은 아직 포함하지 않았다.

### 16.3 검토 반영 (2026-09-27)

같은 날 `gpt-6-astra`(매우높음)에게 전체 구현을 이 문서와 대조해 검토받았다. P0는 없었고, 지적된 결함 중 다음을 그 자리에서 고쳤다.

- 후보 선택 노드가 고정한 후보가 다음 노드 입력으로 전달되지 않던 문제: 입력 소재를 상위 노드 종류별로 계산한다.
- seed를 비우고 후보를 2개 이상 요청하면 두 번째 제출이 중복으로 거부되고 첫 실행이 화면에 남지 않던 문제: 후보가 여러 개일 때만 기준 seed를 만들고, 일부만 제출된 경우도 기록에 남긴다.
- 타이포 큐의 시간·크기만 바꾼 재실행이 같은 입력으로 거부되던 문제: 제출 키에 큐의 시작·끝·크기·글꼴까지 포함한다.
- 구성(MotionSpec) 입력이 과거 실행의 문구까지 함께 렌더하던 문제: 가장 최근 구성만 읽고 큐의 크기·글꼴을 그대로 쓴다.
- MCP 도구가 `isError: true`를 돌려줘도 완료로 기록하던 문제: 실패로 기록하고 사유를 남긴다.
- 저장 중 편집이 저장 완료로 잘못 표시되던 경합: 저장한 문서 스냅샷과 현재 문서가 같을 때만 완료로 표시한다.
- AE 준비 스크립트가 사용자가 열어 둔 프로젝트를 수정하던 문제: 새 프로젝트를 만들고, 열린 프로젝트(저장하지 않은 제목 없는 프로젝트 포함)가 있으면 확인을 받는다.
- AE 준비를 사람이 매번 확인해야 하던 문제: `MODAL_GUI_AE_QUIET=1`로 띄운 AE 인스턴스에서는 확인 대화상자 없이 `.ae.log`에 시작·저장·구성·문구·완료를 남긴 뒤 스스로 종료한다. 사용자의 AE 세션에는 그 환경 변수가 없어 지금처럼 확인 대화상자를 쓴다. 앱은 스크립트와 로그 경로를 만들 뿐 AE를 직접 실행하지는 않으며, 무인 실행은 검증용 직접 실행(`AfterFX.exe -r`)으로 확인했다.
- 제작 화면을 떠나 있는 동안 로컬 렌더가 끝나면 완료가 기록되지 않던 문제: 파이프라인 이벤트를 받는 Rust 쪽에서 실행 행을 닫는다.
- 취소 요청과 취소 확인을 같은 이벤트로 보내던 worker 동작: 요청은 `cancel_requested`, 확인은 원격 호출이 끝난 뒤 `cancelled`로 보낸다.
- 내보내기가 구성 JSON이 참조하는 클립·오디오를 복사하지 않던 문제: 참조 파일을 함께 복사하고 내보낸 사본 경로로 바꾼다(manifest의 `referenced`).
- 재시작 복구가 확인되지 않은 원격 취소를 확정으로 기록하던 문제: 취소로 닫되 "원격 취소 결과를 확인하지 못했습니다"를 함께 남긴다.
- 가져오기가 내보낸 폴더를 그대로 참조하던 문제: 소재와 구성 JSON이 참조하는 파일을 새 프로젝트 폴더로 복사하고, 문서와 구성 안의 경로를 새 위치로 바꾼다(파일 이름 기준으로 맞춰 폴더 접두사가 달라도 동작).
- 프로젝트·노드별 대화가 하나의 모델 스레드를 공유하던 문제: 대화마다 별도 thread를 열고, 응답이 도착한 대화에 답변을 남긴다(대화를 바꿔도 섞이지 않는다).
- 원격 실행 id가 `modal-{job_id}`라는 로컬 값이던 문제: worker가 `spawn()`의 실제 호출 id를 기록한다. 취소 뒤 원격 결과가 남으면 그 원격 경로를 실행 기록에 함께 남긴다.
- 결과 수신부터 복구할 경로가 없던 문제: 취소·다운로드 실패로 끝난 실행은 원격 경로를 남기고, `원격 결과 다시 받기`가 생성은 다시 하지 않고 결과만 다시 내려받는다.
- 생성 노드의 지난 후보가 다음 노드로 모두 흘러가던 문제: 상위 노드는 포트 자료형에 맞는 최신 결과 하나만 내보내고, 후보 비교·고정은 후보 선택 노드가 맡는다. 구성 입력은 최신 구성 JSON 하나만 읽는다.
- 실제 app-server가 `account/login/start.chatgptAuthTokens`에 `experimentalApi` 역량을 요구하던 문제: `initialize`에서 그 역량을 알린다.
- 실제 app-server가 첨부 항목 이름으로 `localImage`·`localAudio`를 쓰던 문제: 서버가 알려준 이름으로 맞춘다(처음 보낸 `local_image`는 서버가 거부했다).
- npm으로 설치한 `codex.cmd`를 CreateProcess가 실행하지 못하던 문제: PATH에서 `codex.exe`를 우선 찾고, 배치 셰임은 `cmd /C`로 실행한다.
- 로그인 콜백 대기 연결이 읽기 타임아웃 없이 열려 있던 문제: 연결마다 2초 읽기 제한을 두어 실패한 시도가 포트를 붙잡지 않게 한다.

같은 날 두 번째 검토에서 검토 이후 변경분(실계정 경로·채팅 첨부·AE 무인 실행)을 다시 대조해 확인된 결함도 그 자리에서 고쳤다.

- 브라우저 자동 열기가 `cmd /C start`로 URL을 넘겨 첫 `&` 뒤가 잘리던 문제: 셸 API(`ShellExecuteW`)로 전체 문자열을 한 인수로 넘긴다. 로컬 서버로 구 방식이 `/old?a=1`만 도달하고 새 방식이 전체 URL을 전달하는 것을 실증했고, 사고 기록에 원인과 검증을 반영했다.
- 콜백 연결의 읽기 제한이 `WouldBlock`을 오류로 취급해 정상 콜백을 버리던 문제: 연결별 최대 2초(시도 마감 이내) 동안 기다린다(`a_delayed_callback_request_is_still_accepted`).
- app-server가 401로 토큰 갱신을 요청해도 만료 시각이 남아 있으면 같은 토큰을 돌려주던 문제: 요청을 받으면 만료와 무관하게 강제로 갱신한다(`force_refresh`).
- 토큰 교환 중 취소한 로그인이 완료·저장되던 문제: 교환 뒤 취소를 다시 확인하고 자격증명을 저장하지 않는다(`cancelling_during_the_token_exchange_does_not_deliver_credentials`).
- AE 스크립트의 실패 경로가 프로젝트 보호 검사·로그를 우회하던 문제: 시작 상태를 `numItems === 0`까지 확인하고, Motion JSON 읽기·형식 오류도 로그와 함께 처리한다.
- AE가 누락 소재나 레이어 0개 프로젝트를 '완료'로 기록하던 문제: 누락 소재·빈 구성을 실패로 기록하고 완료로 남기지 않는다.
- 전달되지 않은 첨부가 화면에 전달된 것처럼 남던 문제: 전송 결과(`delivered`·`note`)를 메시지에 남기고 화면에서 `전달되지 않음`을 구분한다.
- 로그인 대기 중인 시도를 확인할 수 없던 문제: 남은 시간과 취소 동작을 연결 화면에 표시하고, 연 시각·만료·실제 authorize URL을 `logs/chatgpt-login.log`에 남긴다(네이티브 화면에서 4:59 → 4:56 감소와 취소 확인).

고치지 않고 남긴 한계는 다음과 같다.

- 원격 취소 확인: Modal은 실행 취소를 제공하지 않아 취소 요청 뒤에도 원격 생성이 끝날 수 있다. 취소는 `취소 요청됨`으로 남고, 원격이 끝나면 그때 `취소됨`과 원격 경로를 기록한다.
- 원격 호출 id는 worker가 `spawn()`의 실제 호출 id를 기록하도록 고쳤고 단위 테스트로 확인했지만, 실제 H3·YuE2 실행 기록에서 그 값까지 대조하지는 않았다. 취소 뒤 결과 다시 받기는 YuE2 실행에서 확인했고(위 표), H3 영상에서는 아직 확인하지 않았다.
- AE 준비 스크립트(`.jsx`) 안의 구성 경로는 내보내기에서 정확한 문자열 치환만 한다. 접두사가 달라지면 다시 연결해야 한다.
- AE 무인 실행은 앱이 아니라 검증용 직접 실행으로 확인했다. 다른 AE 인스턴스가 이미 떠 있으면 그 인스턴스로 전달되어 대화형으로 동작한다(환경 변수는 새로 띄운 인스턴스에만 적용된다). 자동화 전에 실행 중인 AE가 없는지 확인해야 한다.
- `secrets_included: false`는 JSON 키와 문자열로 저장된 JSON 입력까지 제거하지만, 자유 텍스트에 섞인 비밀값은 자동으로 걸러지지 않는다. 내보내기 전에 도구 입력을 확인해야 한다.
- 화면 이탈 중 로컬 렌더 완료는 Rust가 실행 행을 닫아 기록하지만, 취소·재접속이 필요한 원격 실행의 복구는 공급자가 상태 조회를 제공할 때만 가능하다.

세 번째 검토(수정 확인)에서 남은 경계 조건 3건과 문서 불일치도 함께 고쳤다.

- 전송이 끝나기 전에 도착한 델타·완료를 전송 마무리 코드가 빈 텍스트·`streaming`으로 덮던 문제: 화면이 이미 그 턴을 따라가는 중이거나 이미 끝난 턴이면 상태를 다시 만들지 않는다(`chatDelivery.ts`의 `shouldStartStream` + `store.ts`의 `lastFinishedTurnId`).
- 응답 델타가 전송보다 먼저 도착하면 답변이 이전 대화에 저장되던 문제: 전송 직전에 대화 귀속을 잡고(`shouldBindConversation`), 아직 화면에 반영하지 않은 완료 응답은 건드리지 않는다.
- 이름이 같은 첨부 두 개의 전달 결과가 섞이던 문제: 전달 결과에 소재 경로를 함께 남기고 경로로 맞춘다. 경로가 없는 예전 메시지는 이름으로 맞춘다(`findDelivery`).
- 자격증명 저장이 DB 잠금을 기다리는 동안 취소해도 저장·완료로 남던 문제: 잠금을 잡은 뒤에도 취소를 확인하고, 저장 여부와 취소 여부로 상태를 정한다(`settle_after_store`, Rust 테스트 `a_late_cancel_is_not_reported_as_a_completed_login`).
- 문서: YuE2 취소 복구와 원격 호출 id 검증을 분리하고, 네이티브 화면 조작 검증 완료 범위(파일 선택 대화상자만 남음), 콜백 읽기 제한(연결별 최대 2초), 재시작 취소의 원격 미확인 한계, 실계정 이메일 비식별화를 반영했다.

전송 경로는 실제 TS 모듈(스토어 포함)을 실행해 경계 조건을 확인했고, 네이티브 앱에서 실제 계정으로 한 턴을 보내 답변이 현재 대화에 저장되고 `streaming` 잔여가 남지 않는 것까지 확인했다(2026-09-27 13:23 KST, 사용자 메시지 13:23:18 → 답변 13:23:32).

## 17. 검증할 사용자 흐름

| 시나리오 | 확인할 결과 |
| --- | --- |
| 이미지·영상 첨부 | 드롭·파일 선택·채팅 첨부가 같은 소재를 참조하고 실제 입력 역할을 표시함 |
| 여러 샷과 후보 | 샷 순서와 캔버스 위치가 독립적이며 선택한 후보가 정확히 편집에 들어감 |
| 프롬프트 변경 | 과거 결과를 보존하고 영향받는 결과만 변경 필요로 표시함 |
| 저장 후 앱 재시작 | 캔버스·샷·대화·입력·선택 후보·실행 이력이 복원됨 |
| MCP 연결 실패/인증 만료 | 상태와 복구 행동을 표시하고 프롬프트·파일 입력을 잃지 않음 |

| ChatGPT 로그인·취소·포트 충돌 | 정확한 콜백과 state로 로그인하고 취소·시간 초과·잘못된 콜백을 복구 가능하게 처리함 |
| 토큰 만료와 동시 요청 | 계정별 한 번의 갱신 후 요청을 이어가고 회전한 refresh token을 잃지 않음 |

| OAuth 로그인 후 기능 조회 | 대화·이미지·도구 호출의 실제 지원을 확인하며 API 키 연결로 조용히 전환하지 않음 |
| 미지원 레퍼런스 | 영상/다중 이미지 미지원 도구에 입력을 조용히 누락해 보내지 않음 |
| 중복 클릭·제출 응답 유실 | 실행 제출 여부를 추적하고 확인 없이 중복 생성하지 않음 |
| 실행 중 종료·취소 | 실제 원격 ID와 취소 지원에 따라 상태를 복구하고 불명을 완료로 바꾸지 않음 |
| 생성 성공·다운로드 실패 | 재생성 없이 결과 다운로드부터 복구함 |
| 한국어 타이포 | 원문·글꼴·타이밍이 실제 렌더에서 맞고 필요한 폰트 부재를 표시함 |
| AE 프로젝트 준비 | 준비된 프로젝트와 완성 영상을 명확히 구분함 |
| 여러 계정 실행 | 입력·결과·원격 ID·비용이 의도한 계정에 귀속됨 |
| 프로젝트 내보내기 | 필요한 소재를 복원할 수 있고 인증값이 포함되지 않음 |
| 작은 창·키보드 조작 | 패널을 접어도 생성·선택·저장·복구 기능에 접근 가능함 |

프런트엔드 빌드, 네이티브 컴파일, 로컬 계약 테스트, 실제 Tauri 화면, 외부 도구 실행을 각각 확인한다. 모의 호출 성공이나 브라우저 미리보기만으로 실제 생성·AE 자동화·Modal 복구가 검증됐다고 보고하지 않는다.

2026-09-27 4~5단계 검증에서 확인한 흐름은 한국어 타이포 렌더와 타임라인 편집, 실행 중단 요청과 그 뒤 도착한 결과의 기록과 다시 받기, 같은 입력의 중복 제출 거부, 실행별 비용 구분, 프로젝트 내보내기·가져오기, 노드 그룹 템플릿, 워크플로 두 개를 한 캔버스에서 사용, 실제 계정 로그인과 실모델 대화·첨부 전달, AE 2021 프로젝트 생성과 내용 확인이다. 같은 날 네이티브 앱에서 추가로 확인한 흐름은 다음과 같다.

- 프롬프트·문구를 바꾸면 하위 노드가 `입력 변경됨`으로 표시되고 과거 결과는 그대로 남는다(상위 타이포 노드 수정 → 하위 편집 노드 `완료` → `입력 변경됨`).
- 도구 노드는 사라진 도구(연결 테스트가 캐시에서 지움)·중지된 도구·필수 입력 누락·JSON 형식 오류·객체가 아닌 입력을 실행 전에 알리고 호출하지 않는다(`필수 입력이 빠졌습니다: text` 경고, 실행 거부, 실행 기록 없음).
- 생성 노드에서 고른 Modal 계정이 프로젝트 문서에 남고 실행 요청으로 전달된다(화면에서 선택 → `config.profileId` 저장, Rust 테스트로 작업 기록까지 전달 확인).
- 오른쪽 패널을 접어도 캔버스·실행·저장 동작이 유지된다(접기 → 인스펙터 숨김, 다시 펼치기).

사용자 확인이 남은 흐름은 AE에서의 최종 렌더(프로젝트 열기·구성 확인은 완료), Higgsfield 등 실제 MCP 서버 주소·인증, 네이티브 파일·폴더 선택 대화상자, 등록된 Modal 계정이 하나뿐이라 두 계정 실실행이다.
