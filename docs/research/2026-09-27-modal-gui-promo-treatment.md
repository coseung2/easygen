# Modal GUI 홍보 영상 1차 트리트먼트

작성일: 2026-09-27 · Asia/Seoul

## 방향

우리 앱을 **영상 생성 모델 자체가 아니라, 생성 작업을 정리하고 추적하며 결과까지 관리하는 데스크톱 작업 공간**으로 보여준다. 앞서 분석한 제품 런칭 광고 문법을 사용하되, 현재 앱에서 확인되는 기능만 표현한다.

현재 확인된 제품 사실:

- 이미지와 프롬프트를 입력해 Modal GPU에서 MiniMax H3 오픈소스 모델을 실행한다.
- 영상 생성·음악 생성 모드를 제공한다. 음악 경로는 YuE2로 표현할 수 있다.
- 생성 작업의 계정·워크스페이스 선택, 작업 큐, 단계·로그, 결과 다운로드·재생 흐름을 관리한다.
- 편집·모션그래픽 화면에서 클립, 샷, 타이포그래피 큐, 오디오와 렌더 흐름을 다룬다.
- 사용량 화면에서 Modal 프로필과 사용량 기록을 확인한다.

영상에서는 캔버스 기반 확장 설계, MCP 연결, AI 채팅을 현재 완성 기능처럼 제시하지 않는다. 해당 기능을 넣는 후속 버전에서는 별도 영상으로 만든다.

## 추천 콘셉트

**제목:** `From prompt to finished frame.`

**부제:** `Generate. Track. Refine.`

**길이:** 26초 · 16:9 우선, 이후 9:16 재구성

**느낌:** Google/SaaS 런칭 광고의 넓은 여백과 제품 UI 중심 연출. 화면 바탕은 따뜻한 아이보리와 차콜을 사용하고, 앱의 상태 변화에는 전기 블루를 사용한다. H3 영상 결과와 YuE2 오디오에는 보라색을 보조색으로 사용한다. 제품 UI의 실제 색을 임의로 바꾸지 않고 배경·카드·강조색으로 분위기를 만든다.

**핵심 메시지:**

> 생성 버튼 하나보다 중요한 건, 생성이 끝날 때까지의 흐름을 잃지 않는 것.

카피는 영어를 기준으로 잡았지만 제품의 주 사용자가 한국어라면 다음 한국어 버전을 사용한다.

```text

무엇이 실행됐는지 확인하세요.
Modal GUI — 통제하며 만드세요.
```

## 연출 규칙

- UI는 실제 앱 화면을 캡처하거나 실제 컴포넌트와 데이터를 사용해 재현한다. AI 영상 모델에 화면 전체를 다시 그리게 하지 않는다.
- 입력 이미지, 프롬프트, 버튼, 작업 단계, 결과 파일명, 타임라인, 사용량 숫자는 읽을 수 있어야 한다.
- 한 컷에서 UI 전체를 설명하지 않는다. 확대할 기능 하나만 남기고 주변은 흐리거나 어둡게 한다.
- 연결되는 요소를 계속 유지한다. 입력 이미지 카드는 생성 작업 카드의 썸네일이 되고, 결과 카드는 편집 타임라인의 클립이 된다.
- 커서는 장식이 아니라 행동을 표시한다. 입력, 생성, 결과 열기, 타임라인 배치에만 사용한다.
- 작업 단계가 빨리 끝나는 것처럼 편집하지 않는다. 실제 실행 시간이나 비용을 주장하지 않고, 상태가 어떻게 바뀌는지만 보여준다.
- 사용량 장면에서는 “저렴하다”, “무료다”라고 말하지 않는다. 제품은 관측 사용량과 실제 청구 확인을 구분한다.
- 화면 전환은 12–20프레임의 부드러운 이동을 기본으로 하고, 상태 전환은 짧은 페이드·슬라이드로 처리한다. 모든 요소에 글로우나 바운스를 넣지 않는다.

## 제작 파이프라인

```text
실제 앱 화면 캡처
    ↓
개인정보·토큰·로컬 경로 제거
    ↓
홍보용 테스트 데이터와 샘플 결과 준비
    ↓
샷별 화면 크롭·포커스 영역 지정
    ↓
AE 또는 코드로 카드·커서·상태·타이포 애니메이션
    ↓
앱 결과 영상과 음악을 실제 파일로 교체
    ↓
16:9 출력 → 9:16 재배치 → 문구·가독성 검토
```

### 필요한 실제 소재

1. 앱의 Generate 화면 캡처: 이미지 입력, 프롬프트, `영상 생성` 버튼이 보이는 상태.
2. Jobs 화면 캡처: 진행 중 단계와 로그가 보이는 상태.
3. 결과 화면 캡처: 실제 생성 영상의 썸네일과 재생 화면.
4. Edit · 모션그래픽 화면 캡처: 샷, 클립, 타이포 큐, 오디오 파형이 보이는 상태.
5. Usage 화면 캡처: 민감한 계정명·경로·금액을 제거한 테스트 상태.
6. 최종 결과에 사용할 실제 앱 생성 클립 1개와 음악 1개.

앱 캡처에 실제 Modal 프로필 이름, 이메일, 토큰, 로컬 드라이브 경로, 개인 파일명이 보이면 마스킹한 뒤 사용한다. 제품 기능을 보여주기 위한 화면에는 테스트 데이터와 실제 결과를 구분해 저장한다.

## 첫 번째 제작본의 기준

- 영상 파일: 1920×1080, 30fps, 26초.
- 원본: AE 프로젝트 또는 코드 기반 렌더 프로젝트와 모든 캡처·폰트·오디오를 함께 보관.
- 별도 출력: 1080×1920 세로 버전. 세로에서는 UI 전체를 억지로 축소하지 않고 입력·상태·결과 세 장면으로 재구성.
- 검토: 제품 화면의 사실성, 카피 정확성, 개인정보 제거, UI 읽기 시간, 상태 변화의 인과관계, 실제 결과 파일 재생.
