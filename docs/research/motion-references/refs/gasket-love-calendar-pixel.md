## 한 줄 요약

작은 캘린더 위젯에서 픽셀 경계로 데스크톱을 펼치고, 일정 입력 필드를 차례로 확대해서 보여 준 뒤 등록 동작과 함께 다시 위젯으로 돌아오는 16초 모션.

## 구간표

전체 약 0.50초 간격의 표본에 근거한 대략적인 구간. 3.5–4.7초 전환부는 약 0.075초 간격으로 추가 확인했다.

| 구간 | 화면 관찰 | 역할에 대한 해석 |
| --- | --- | --- |
| 0–1초 | 밝은 회색 바탕, 중앙의 작고 둥근 흰 캘린더, 부드러운 그림자 | 출발 대상을 고정하고 넓은 여백으로 집중 |
| 1–3.5초 | 커서 이동, 16–19일 범위 강조, New Event 메뉴 | 일정 등록이라는 행동의 원인을 먼저 보여 줌 |
| 3.5–4.7초 | 위젯 주변에 분홍·주황 배경이 작은 사각형 경계로 퍼짐, Dock과 일정 창 등장, 위젯은 왼쪽 아래로 이어짐 | 기존 대상을 보존하면서 더 큰 작업 공간을 공개 |
| 4.7–6.8초 | 데스크톱 전체를 잠깐 보여 준 뒤 제목 입력란 확대, Design Sprint 입력 | 전체 맥락에서 입력 초점으로 이동 |
| 6.8–8.3초 | 위치 필드로 시점 이동, Studio 3, Seongsu 입력, 참석자 아바타 유지 | 카메라가 현재 행동을 따라가게 함 |
| 8.3–10.3초 | 메모 필드로 이동, Kickoff, wireframes, review — ship Friday 입력 | 입력 순서를 화면 이동과 연결 |
| 10.3–11.8초 | 전체 창으로 물러남, 커서가 Add Event로 이동, 버튼이 분홍빛으로 강조 | 상세 입력을 끝내고 완료 행동에 주목 |
| 11.8–13.7초 | 일정 창이 축소·이동하며 사라지고 데스크톱 배경 가장자리에 픽셀 경계가 나타남 | 입력 공간을 접고 원래 대상에 복귀 |
| 13.7–16.04초 | 중앙 위젯과 넓은 여백으로 돌아와 날짜 범위 강조 유지 | 시작 구도를 회수하면서 변경된 상태를 남김 |

이 영상은 모션 연습이다. 실제 앱의 클릭·등록·데이터 저장이 동작한다는 증거는 아니다. 시작과 끝의 구도는 유사하지만 날짜 선택 상태가 다르므로 완전한 무봉제 루프로 분류하지 않는다.

## 가져올 것

- **기준 대상 보존:** 캘린더를 화면 전환 전후에 남겨 위젯→데스크톱→위젯을 하나의 사건으로 읽게 한다.
- **전환 경계에 픽셀 사용:** 화면 전체를 계속 거칠게 만들기보다 배경이 나타나고 사라지는 경계에 사각형 패턴을 집중한다. 정확한 텍스트·UI는 정착 뒤 선명하게 보여 준다.
- **행동 순서와 확대 순서 일치:** 제목→위치→메모→등록 버튼. 카메라 이동을 장식 대신 시선 안내로 쓴다.
- **빠른 이동과 읽는 정지의 교대:** 전환 중에는 흐림이 보이고 입력 구간에서는 글자를 읽을 수 있다. 이징·블러 구현 방식은 확인하지 않았다.
- **색으로 상태 강조:** 날짜 선택의 붉은색, 배경의 따뜻한 분홍·주황, 등록 버튼의 강조색이 연결된다. 평상시 패널은 흰색·회색 중심이다.
- **우리 제작용 제안:** 서비스의 작은 카드 하나를 출발점으로 잡고 상세 작업 공간을 펼친 뒤, 입력 결과가 남은 같은 카드로 복귀한다. UI·텍스트는 편집 가능한 레이어로, 픽셀 전환은 격자 마스크로 구현할 수 있다. 이는 AE·코드 재현 제안이며 원작 기술을 확인한 결과가 아니다.

인용 예: `ref: gasket-love-calendar-pixel 3.5–4.7초 기준 위젯을 남긴 픽셀 리빌, 5–10초 입력 필드를 따라가는 확대, 12–16초 결과 상태로 복귀`.

## 피할 것

- 전환 효과가 입력 내용까지 오래 가려 기능 시연을 읽을 수 없게 만드는 것.
- 클릭·입력과 무관한 확대를 반복해 시선을 분산시키는 것.
- 이 영상의 작은 초기 달력을 그대로 축소해 세로판에 넣는 것. 모바일용은 캘린더 크기·필드별 화면 점유율을 다시 잡는다.
- 닫히는 창만으로 저장 성공을 주장하는 것. 실제 제품 시연에서는 등록된 일정이나 완료 상태를 확인 가능하게 보여 준다.
- 원본 OS 아이콘·인물 아바타·배경을 그대로 재사용하는 것. 우리 서비스의 화면과 권한 있는 소재로 대체한다.

## 확인 못 한 것

- 렌더러·라이브러리·AE 사용 여부·제작 코드·프롬프트·원본 해상도·편집 과정.
- 픽셀 크기·랜덤 시드·정확한 전파 방향·이징·모션 블러 설정. 프레임에서 보이는 외형만 관찰했다.
- 음악·효과음과 클릭 타이밍의 관계. 오디오 스트림은 존재하나 청취·전사하지 않았다.
- 작성자가 언급한 이전 픽셀 트랜지션 게시물은 이번 분석에 포함하지 않았다.
