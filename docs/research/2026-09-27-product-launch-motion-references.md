## 1. 무엇을 확인했는가

기본 표본은 전체 흐름 확인용이며 정확한 컷 경계 검출 결과가 아니다. 세부 표본은 0.4–1초 간격이다. 아래 시간은 대략적인 구간이고 원본 키프레임·이징 수치를 복원한 것은 아니다. 자동자막은 주로 음악·불완전한 발성 인식이어서 제품 카피의 근거로 사용하지 않았다. 화면에 표시된 내용과 제작자 설명란을 우선했다. 오디오의 BPM·박자와 전환의 정확한 동기화는 이번 분석에서 검증하지 않았다.

## 2. ‘구글 광고 같다’는 인상의 구성 요소

첫 영상은 제작자가 구글 광고 참고를 직접 밝힌다. 다른 세 편까지 구글의 영향을 받았다고 단정할 근거는 없다. 다만 시각적으로 공유하는 문법은 다음과 같다.

| 공통 문법 | 화면에서 하는 일 | 우리 작업 지시로 바꾸면 |
| --- | --- | --- |
| 짧은 타이포 | 한 단어나 짧은 문장을 중심에 두고 다음 의미로 교체 | 한 장면에서 가장 중요한 주장 하나를 먼저 보이게 한다 |
| 넓은 여백 | 작은 입력창·아이콘에도 시선을 모음 | 모든 공간을 장식으로 채우지 않고 초점 주변을 비운다 |
| 브랜드 그라데이션 | 흰 화면과 컬러 화면을 묶고 장면 전환의 분위기를 유지 | 브랜드 색을 정하고 배경·강조·테두리에 반복한다 |
| UI의 선택적 확대 | 실제 화면 전체와 버튼·카드 같은 세부 요소를 번갈아 보여줌 | 지금 설명하는 행동과 결과만 읽을 수 있게 확대한다 |
| 상태 변화 | 입력→처리→결과, 선택→변환, 초대→협업을 보여줌 | 모션마다 사용자의 행동이나 제품의 결과를 연결한다 |
| 요소의 연속성 | 같은 카드·모서리·중심 위치를 다음 화면에도 이어감 | 각 컷의 마지막 요소가 다음 컷에서 무엇이 되는지 정한다 |
| 제한된 깊이감 | 카드의 기울기·겹침·그림자로 공간을 만듦 | 입체 연출 후 중요한 UI는 읽기 좋은 각도로 정착시킨다 |
| 변화와 유지의 교대 | 빠른 타이포 뒤에 기능 화면, 마지막에 브랜드 유지 | 움직이는 구간과 이해·읽기 구간을 나누어 설계한다 |

구글의 네 가지 색이나 특정 글꼴만으로 정의되는 스타일은 아니다. 이번 네 영상에서도 파랑·청록, 분홍·주황·보라 등 팔레트는 다르다. 공통점은 **제품을 쉽게 이해할 수 있도록 정보의 양과 시선을 조절하는 연출**이다.

Lovable은 다른 세 편보다 따뜻한 분홍·주황, 진한 검정, 밝은 크림색, 거친 입자감과 강한 빛의 대비가 두드러진다. 구글풍이라는 한 표현에 모두 넣기보다 **표현적인 그라데이션 브랜드 + 제품 시연**으로 따로 저장하는 것이 유용하다.

앞선 Sunbeam은 타이포·입체 소재·팝 그래픽의 대비 자체가 표현의 중심이었다. 이번 영상들은 사용자의 행동과 제품의 변화가 이야기의 중심이다. 기존의 ‘혼합 미디어 쇼릴’과도 구별된다. 결과물을 나열하는 데서 더 나아가 어떻게 입력하고 무엇이 바뀌는지 보여주기 때문이다.

작업용 스타일 분류에 다음 네 가지를 추가한다. 이는 시장의 공인 명칭이 아니라 레퍼런스를 다시 찾고 작업 방향을 선택하기 위한 내부 분류다.

- 미니멀 제품 런칭: 타이포·아이콘·간단한 사용 흐름.
- 입체 UI 카드 모션: 카드·디바이스·처리 상태의 가벼운 공간 연출.
- 업무 흐름 설명형: 문제·단계·결과를 따라가는 설명.
- 그라데이션 브랜드 런칭: 강한 브랜드 미술과 실제 기능 시연의 결합.

## 5. 우리 제작 파이프라인

원작의 제작 파일은 확보하지 않았으므로 아래는 관찰한 결과를 구현하기 위한 제안이다. 첫 영상 외에는 사용 렌더러를 확정하지 않는다.

```text
제품에서 확인된 사실 + 전달할 가치 한 가지
    ↓
사용자 행동·결과 선택
    ↓
카피·장면 계획 + 장면 사이에 이어갈 요소 지정
    ↓
브랜드 기준 + UI 원본/정확한 화면 소재
    ↓
핵심 화면 3–5장 + 움직임을 확인할 저해상도 초안
    ↓
UI 상태·커서·텍스트·카드·배경을 독립 레이어로 제작
    ↓
AE 또는 코드로 타이밍·전환·카메라 구성
    ↓
사운드·읽기 시간·부분 수정·출력
```

### 소재를 만드는 기준

- 제품 화면은 사용자에게 공개 가능한 정확한 원본을 쓴다. 시각적 단순화가 필요하면 중요한 정보와 행동을 보존한 그래픽으로 재구성한다.
- 기능 설명에 쓰는 글자, 숫자, 버튼, 커서는 편집 가능한 요소로 만든다. 화면에 보이지 않는 기능을 실제 작동하는 기능처럼 발명하지 않는다.
- 전체 화면과 확대할 영역을 함께 준비한다. 화면 한 장만 늘리면 글자가 흐려지므로 충분한 해상도나 벡터·HTML 요소를 확보한다.
- 배경·글로우·그레인·아이콘·UI·커서·텍스트·그림자를 분리한다. 글로우가 UI의 작은 글자까지 덮지 않게 한다.
- 제품의 실제 입력·로딩·완료 상태와 광고 편집상의 시간 압축을 구별한다. 장면의 빠른 완료를 실제 성능 측정치처럼 제시하지 않는다.

### AI의 역할과 렌더러의 역할

| 역할 | 적합한 작업 |
| --- | --- |
| AI 기획·분석 | 레퍼런스 분해, 핵심 가치·카피 초안, 샷 구성, 전환 아이디어 |
| AI 이미지·영상 | 필요한 제품 외 소재, 추상 이미지, 짧은 분위기 영상, 결과물 예시의 허용된 소재 |
| AI 코딩·AE 조작 | 컴포지션 생성, 반복 카드 배치, 타이핑·커서·변형·카메라 구현, 부분 수정 |
| AE/코드 렌더 | 글자·UI 보존, 프레임별 타이밍, 레이어 순서·마스크·그림자·합성 |
| 사람의 판단 | 실제 기능과 메시지의 일치, 시선, 읽기 시간, 브랜드 적합성, 최종 선택 |

이 계열에서 생성 영상 모델을 기본 엔진으로 삼으면 UI 글자·버튼 위치·동작의 인과관계를 유지하는 부담이 커진다. 생성 모델은 필요한 소재나 샷에 사용하고, 제품 설명의 중심은 제어 가능한 레이어로 두는 것을 권한다. 이는 우리 제작 방향 제안이며 네 원작의 제작 방법을 추정해 확정한 주장이 아니다.

단순 전환 프리셋뿐 아니라 `사용자 행동 → 시스템 변화 → 보이는 결과`를 묶어서 저장하는 것이 좋다. 단, 하나의 규격으로 모든 광고를 찍어내지 않도록 미술과 타이밍은 개별 조절한다.

### 시간 설계의 출발점

다음 수치는 원영상에서 측정한 값이 아니라 첫 초안용 제안이다. 30fps를 예로 든다.

- 짧은 속성 변화: 6–12프레임, 약 0.2–0.4초.
- 주된 카드·화면 전환: 12–24프레임, 약 0.4–0.8초.
- 카드들 사이 등장 간격: 2–4프레임부터 시험.
- 한 가지 결과를 이해할 정착 시간: 0.8–1.5초부터 시험하고 글이 길면 연장.
- 마지막 로고·주소: 1.5–2.5초부터 시험.

가속·감속이 있다고 해서 매번 튕길 필요는 없다. 빠른 이동 뒤 또렷하게 정착시키고, 커서가 도착하기 전에 버튼이 눌리거나 결과가 나타나는 인과관계 오류를 피한다. 원영상의 정확한 이징 곡선을 알아냈다고 주장하지 않는다.

## 8. 제작·검토 체크

- 글자와 UI는 최종 시청 크기에서 읽히는가. 회전·글로우·블러가 끝난 뒤 읽을 수 있는가.
- 커서·선택·클릭·결과의 순서가 맞는가. 사용자가 무엇을 했는지 보이는가.
- 하나의 전환에서 중심·색·형태·방향 중 적어도 무엇이 이어지는가.
- 같은 카드가 다른 장면에서 이유 없이 외형·크기·문구를 바꾸지 않는가.
- 모든 요소가 동시에 움직여 초점이 사라지지 않는가.
- 브랜드의 색·둥근 정도·그림자·타이포가 반복되는가.
- 광고의 기능·사실·수치가 실제 근거와 일치하는가.
- 문구·카드 내용·브랜드색을 바꾸더라도 전체 영상을 재생성할 필요가 없는가.
- 처음·중간·끝의 정지 화면뿐 아니라 재생 중에도 의도와 읽기 시간이 유지되는가.
