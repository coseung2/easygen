# AI 모션그래픽 제작 흐름과 스타일 분석

분석일: 2026-09-27 · Asia/Seoul

후속 분석: [구글 광고 감성·SaaS 제품 런칭 모션 4편](2026-09-27-product-launch-motion-references.md) — Google Fake, LangEase, Numtera, Lovable 2.0의 UI·카피·전환과 제작 적용안.

핵심 판단: 우리 작업에는 **AI가 기획·소재 제작을 맡고, 코드 또는 After Effects가 정확한 타이포·움직임·편집을 맡는 방식**을 기본으로 삼는 것이 적합하다. 영상 생성 모델은 캐릭터 동작, 질감 변화, 실사와 초현실적 장면 등 필요한 샷에 선택적으로 사용한다. 결과 영상뿐 아니라 수정 가능한 원본을 남기는 것이 중요하다.

이는 제공된 영상과 공식 자료를 바탕으로 한 제작 제안이다. 모델 성능을 직접 비교하거나 우리 환경에서 제작 시간을 측정한 결과는 아니다.

자동자막에는 제품·모델 이름 오기가 있다. 화면 및 설명란과 대조했으며, 영상 속 모델명은 해당 제작자가 사용·소개한 명칭으로 취급한다. 네 편의 최근 튜토리얼과 한 편의 과거 작품은 시장 전체를 대표하는 표본이 아니며, 도구 홍보 링크와 성공 사례 위주 편집도 포함한다. 따라서 비용 우위·성공률·제작 시간에 관한 발표자의 말을 일반적인 보장으로 확대하지 않는다.

## 3. 이 표본에서 보이는 제작 흐름의 변화

1. **AI의 역할이 기획에서 실행까지 넓어진다.** 브리프 해석, 소재 생성 호출, 파일 배치, 애니메이션 코드 작성, AE 조작, 렌더까지 연결된다. MCP는 이 연결 수단이며 화질이나 연출 수준을 보장하는 모델이 아니다.
2. **레퍼런스가 취향 전달 자료이자 제작 명세의 입력이 된다.** 팔레트·질감만 추출하면 부족하다. 무엇이 언제 들어오고, 무엇이 남으며, 어떻게 다음 장면으로 넘어가는지까지 분해한다.
3. **짧은 요청 뒤에 상세한 조건이 들어간다.** 영상 속 한 줄 요청은 가이드, 첨부 이미지, 과거 대화, 도구 연결을 전제로 한다. 재현하려면 이 맥락을 파일과 규칙으로 남겨야 한다.
4. **생성 소재와 정확한 그래픽을 섞는다.** 분위기·질감·복잡한 동작은 생성 모델로, 정확한 문구·수치·정렬은 텍스트·벡터 레이어로 관리하는 조합이 정보 전달에 유리하다.
5. **최종 MP4와 함께 수정 가능한 원본이 중요해진다.** 색·폰트·타이밍·레이어를 바꾸는 사례가 반복된다. 첫 생성보다 수정의 범위와 재사용성이 작업 효율을 좌우한다.
6. **디자인 판단은 여전히 남는다.** C의 세밀한 위치·두께 조정, B의 구름 교체, E의 스타일 선택이 이를 보여 준다. 자동 실행을 곧바로 자동 아트디렉션의 완성으로 해석하면 안 된다.
7. **스타일 자체와 새 제작 방식을 구별해야 한다.** 종이 콜라주, 키네틱 타이포, 팝 그래픽은 오래된 디자인 언어다. 이 자료에서 새롭게 주목할 변화는 그 언어를 자연어와 에이전트로 제작·수정하는 접근성이다.

## 4. 세 가지 제작 파이프라인

| 경로 | 구성 | 적합한 작업 | 유지되는 수정 가능성 | 주의점 |
| --- | --- | --- | --- | --- |
| 영상 생성 | 브리프 → 연출 지시서 → 참조 이미지/영상 → 영상 모델 → 후보 선택 | 짧은 감각적 광고, 캐릭터 동작, 유기적인 변화 | 프롬프트·참조·생성 설정 | 특정 글자 하나나 위치 하나의 수정에 재생성이 필요할 수 있음 |
| 이미지 + 코드 | 브리프 → 배경·전경·캐릭터 포즈 생성 → 분리·정렬 → Python 등의 코드 → 렌더 | 종이 컷아웃, 지도, 디오라마, 반복 모션, 타이포 | 소재, 장면 명세, 코드 | 좌표·앵커·알파가 불안정하면 떨림·가장자리 문제가 생김 |
| AI + AE | 브리프·스타일 → 소재 제작 → 컴포지션·텍스트·도형·키프레임 → 프리뷰 → 부분 수정 | 한글 중심 영상, 로고, 브랜드 모션, 정보 그래픽, 혼합 합성 | AE 프로젝트의 네이티브 레이어·키프레임 | 버전·폰트·플러그인·실제 연결 호환성 확인 필요 |

우리 기본 경로 제안:

```text
브리프·정확한 카피·자료
       ↓
레퍼런스 분석 → 스타일 기준 + 움직임 기준
       ↓
샷 계획 + 음악/나레이션의 주요 시점
       ↓
스타일 프레임 → 저해상도 애니매틱 → 방향 선택
       ↓
샷에 맞는 제작 경로 선택
       ├─ 글자·로고·도형 → AE 또는 코드
       ├─ 종이·지도·디오라마 → 분리 이미지 + 코드/AE
       └─ 실사·유기적 동작 → 영상 생성
       ↓
통합 타임라인 → 타이포·사운드 합성 → 부분 수정 → 출력
```

Remotion은 코드 경로의 선택지다. 공식 문서는 에이전트 스킬을 제공한다. 다만 B의 이번 시연에서 필수 도구가 아니며, C의 실제 엔진이라고 확인된 것도 아니다. 렌더러를 추가하기 전에 기존 AE·코드 경로가 요구를 충족하는지 확인하는 편이 좋다. [Remotion 공식 스킬 문서](https://www.remotion.dev/docs/ai/skills)

아래 제작 경로는 관찰한 스타일을 우리 환경에서 구현하기 위한 제안이다. 원작자가 실제 사용한 소프트웨어를 뜻하지 않는다.

| 스타일 | 시각적 규칙 | 주요 움직임 | 권장 경로·소재 | 근거 |
| --- | --- | --- | --- | --- |
| 미니멀 키네틱 타이포 | 흑백, 큰 글자, 강한 정렬, 한 가지 강조색 | 단어별 등장, 확대, 반전, 마지막 정지 | 텍스트·SVG + AE/코드 | A 05:45, C 01:57 |

| Y2K 팝·입체 타이포 | 코발트 계열, 젤리/광택, 방사형 패턴, 얇고 굵은 글자 대비 | 슬라이스, 트레일, 회전, 급격한 구도 변화 | 입체 소재 + 벡터/텍스트 합성 | D 전반 |

## 6. 우리 스튜디오에 필요한 작업 단위

현재 [스튜디오 설계](../creative-studio-architecture.md)의 캔버스·스토리보드·타임라인 구분은 이 제작 흐름과 맞는다. 다음은 설계에 추가 검토할 항목이며 이번 조사에서 구현하지 않았다.

| 작업 단위 | 저장할 내용 | 필요한 이유 |
| --- | --- | --- |
| 레퍼런스 분석 | 원본 링크, 선택 구간, 대표 프레임, 관찰, 추론, 적용할 규칙 | 취향 설명을 재사용 가능한 지시로 변환 |
| 스타일 기준 | 색·글꼴 파일·그리드·재질·테두리·그림자·금지 요소 | 샷마다 미술이 바뀌는 현상 방지 |
| 모션 기준 | 등장·유지·퇴장 시간, 이동 방향, 지연 간격, 이징, 카메라 | 같은 스타일에서도 움직임이 제각각인 문제 방지 |
| 샷 명세 | 목적, 정확한 문구, 구도, 길이, 소재, 제작 경로 | 어떤 샷만 수정·재생성할지 결정 |
| 소재 준비 | 알파, 캔버스 크기, 기준점, 레이어 역할, 포즈 순서 | 종이·캐릭터·디오라마의 정렬 안정화 |
| 후보 선택 | 선택한 결과, 탈락 이유, 비교용 프레임, 원본 실행 정보 | 이전에 좋았던 결과를 잃지 않음 |
| 타임라인 | 컷·레이어·텍스트·나레이션·음악·효과음 | 생성 영상과 편집 가능한 요소를 정확히 합성 |
| 부분 수정 | 샷/레이어, 시간 구간, 변경 속성, 보존 대상 | 수정할 때마다 완성한 부분이 흔들리는 문제 감소 |

참조는 적어도 `스타일`, `제품/캐릭터 정체성`, `구도`, `모션`, `시작/끝 프레임` 역할을 구별한다. 이미지 한 장에서 알 수 없는 움직임은 확정하지 않고 추론으로 표시한다. 정체성 참조를 쓰려는 실행 도구가 해당 입력을 지원하는지도 별도로 확인한다.

재사용할 모션 묶음은 우선 다음 정도면 충분하다: 단어·글자 순차 등장, 마스크 리빌, 반복 트레일, 블록 전환, 경로 그리기, 패럴랙스, 포즈 루프, 마지막 로고 유지. AE는 문자별 애니메이터와 선택자를 공식적으로 제공한다. [Adobe 텍스트 애니메이션 문서](https://helpx.adobe.com/after-effects/desktop/animating-text/text-animation/animating-text.html)

제품 UI에서는 제작 목적을 중심으로 표현하되, 실행 이력에는 모델·렌더러·입력·폰트·프롬프트·설정·결과를 보존한다. AI와 나눈 대화 전체가 실제 실행 조건을 대신하지 않는다.

## 7. 바로 적용할 제작 절차

1. **메시지 고정:** 대상, 전달할 한 문장, 필수 카피, 확인된 제품 사실, 길이·비율을 정한다.
2. **레퍼런스 분업:** 한 자료에서는 색·재질, 다른 자료에서는 타이포·리듬, 또 다른 자료에서는 전환을 선택한다. 특정 작품 전체를 통째로 따르는 대신 적용 규칙을 적는다.
3. **샷 계획:** 각 샷의 정보와 시각적 역할을 한 문장으로 쓴다. 글자가 움직인다는 설명보다 왜 그 단어가 그 시점에 커지는지 정한다.
4. **스타일 프레임 확인:** 시작·중간·마지막 등 핵심 화면을 정지 상태로 확인한다. 글자가 너무 작거나 구도가 약한 문제를 비싼 영상 생성 전에 수정한다.
5. **애니매틱 확인:** 임시 이미지와 저해상도 렌더로 컷 길이, 읽는 시간, 나레이션, 음악의 주요 시점을 맞춘다.
6. **소재 제작·분리:** 배경, 전경, 제품, 캐릭터, 장식, 그림자, 정확한 글자를 나눈다. 같은 캐릭터의 포즈는 크기·시점·기준점을 맞춘다.
7. **샷별 실행:** 필요한 부분만 영상 생성하고, 타이포·지도·로고 등은 편집 가능한 방식으로 만든다.
8. **시간·요소 단위 수정:** 예를 들어 `샷 2, 3.0–3.6초, 제목만 크기 조정, 배경과 음성은 유지`처럼 지정한다.
9. **출력과 보존:** MP4와 함께 사용한 소재, 실제 폰트, 장면 명세, 코드 또는 AE 프로젝트, 선택 이력을 남긴다.

음악은 항상 마지막에 붙이는 것으로 고정하지 않는다. 나레이션 중심 설명 영상은 발화 길이를 먼저 잡고, 음악 중심 쇼릴은 곡의 구조를 먼저 잡는다. 로고 인트로는 시각적 임팩트 시점을 정하고 효과음을 맞출 수 있다. 어느 쪽이든 최종 타임라인에서 소리와 화면을 함께 검토해야 한다.

### 10초 타이포 영상의 샷 계획 예시

아래는 분석에서 도출한 자체 제안이며 원영상의 제작 지시서를 복제한 것이 아니다.

| 시간 | 역할 | 화면·움직임 | 제작 방식 |
| --- | --- | --- | --- |
| 0.0–1.5초 | 시선 확보 | 짧은 핵심어 한 개, 작은 움직임 후 큰 크기 대비 | 텍스트·도형 |
| 1.5–4.0초 | 내용 전개 | 2–3개 키워드를 시간차로 연결 | 텍스트·선·마스크 |
| 4.0–6.5초 | 시각적 변주 | 핵심 키워드 반복·트레일, 필요하면 이미지 소재 | AE/코드 + 이미지 |
| 6.5–8.0초 | 메시지 회수 | 요소가 정렬되어 브랜드 문구로 모임 | 텍스트·레이어 |
| 8.0–10.0초 | 기억·읽기 | 로고와 짧은 문구 유지, 소리 정리 | 정확한 로고·텍스트 |

타이밍은 문구 길이와 음악에 맞춰 조절한다. 생성 모델에 적는 초 단위 지시는 목표이며, 정확한 프레임 제어가 필요하면 편집 타임라인에서 확정한다.

## 8. 도입 우선순위와 검증

처음에는 세 종류만 만들어 제작 경로를 비교하는 것을 제안한다. 이번 조사에서는 이 샘플을 실제 제작하지 않았다.

| 순서 | 샘플 | 확인할 핵심 |
| --- | --- | --- |
| 1 | 10초 한글 키네틱 타이포 | 정확한 문구·폰트, 마지막 읽는 시간, 특정 시점 색·크기 수정 |
| 2 | 12–15초 종이 디오라마 | 소재 분리, 기준점, 패럴랙스, 반복 동작의 이음새 |
| 3 | 15초 제품 또는 정보 영상 | 생성 영상 + 정확한 오버레이, 샷 연결, 제품 외형·주장 확인 |

그다음 Sunbeam 같은 복합적인 팝 타이포 스타일을 확장한다. 기본 타이밍과 레이어 수정이 안정되지 않은 상태에서 효과 종류부터 늘리면 결과의 통일성을 평가하기 어렵다.

검토할 항목:

- 문구·숫자·로고가 정확한가. 글리프 누락·폰트 대체·잘림이 없는가.
- 화면의 핵심이 분명하고 문구를 읽을 시간이 있는가.
- 샷 사이 팔레트·재질·캐릭터·제품 정체성이 유지되는가.
- 포즈 루프의 첫/끝, 알파 경계, 전경 이동 후 드러나는 배경에 결함이 없는가.
- 동작에 시작·변화·정착이 있고, 모든 요소가 똑같이 확대·흔들리기만 하지는 않는가.
- 완성한 부분을 보존하면서 특정 요소만 수정할 수 있는가.
- 프리뷰와 최종 출력의 비율·프레임률·길이·소리가 맞는가.

비용은 발표자의 빠른 성공 사례 대신 `기획·소재 생성·재생성·렌더·수정 시간`을 나누어 기록한다. 유료 생성 횟수와 채택률을 함께 보면, 처음 저렴했던 경로가 수정 과정에서도 저렴한지 판단할 수 있다. 로컬 렌더는 생성 크레딧을 줄일 수 있어도 구독·도구·연산·작업 시간까지 무료라는 뜻은 아니다.

우리 도구 조합은 AI 에이전트의 기획·실행, 필요한 이미지·영상 생성, AE/코드의 정확한 그래픽·합성, FFmpeg 등의 출력으로 구성할 수 있다. 기존 Modal/Comfy 경로도 샷에 맞는 공급 경로로 둘 수 있다. 다만 이번 조사는 해당 연결의 실행 성공, AE 2021 호환성, 서비스 가격·쿼터를 검증한 작업이 아니다.

## 9. 자료 보관과 재확인

원본 메타데이터·자막·분석용 영상·스크립트·추출 프레임은 다음 로컬 폴더에 보관했다. 저장소에는 분석 문서와 후속 제품 런칭 레퍼런스 문서만 추가했다.

로컬 분석 작업 디렉터리(저장소 밖)

- `<영상ID>.metadata.json`: 제목, 게시일, 설명, 챕터를 추린 정보.
- `<영상ID>.ko-orig.txt`: 튜토리얼 한국어 자동자막과 시각. 자동자막 오기가 있으므로 원문 인용·고유명사 확인 시 화면과 대조.
- `inspection-manifest.json`: 다운로드본의 길이·해상도·fps, 기본 표본 시각.
- `<영상ID>.sheet.jpg`: 영상별 기본 프레임 목록.
- `sunbeam-motion.jpg`, `generated-type-motion.jpg`, `showreel-motion.jpg`: 추가 연속 프레임.
- `inspect_sources.py`, `make_sheets.py`, `detail_sheets.py`: 분석 보조 스크립트.

일부 영어 자막 요청은 HTTP 429로 실패했으나 분석에 사용한 한국어 자막과 다섯 영상 파일은 수집됐다. 웹 도구의 YouTube 직접 열기는 실패하여 영상 본문 확인에는 yt-dlp 수집본을 사용했다. 공식 웹 자료는 연결 방식과 편집 기능의 보조 확인에 사용했다.
